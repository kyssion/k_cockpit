## 背景

系统首次部署时**没有任何账号**，而所有管理接口都需要认证——这里存在一个自举（bootstrap）问题：创建首个管理员的入口本身不可能需要认证。

现有文档没有定义这条路径。`PRD.md` 的 F-1-04 是**登录之后**的安全初始化引导（SMTP / 邮箱 / 2FA），F-9-06 是面板不可用时的**带外重置**脚本，两者都不是「首次创建管理员」。`f-1-01` 的令牌分级里预留了 `bootstrap` 类型（仅可访问安全初始化接口），但对应的流程一直未定义。

参考项目 [QVMConsole](../08-reference/qvmconsole/README.md) 的做法是：首次启动自动创建 `admin / admin123` 并提示立刻改密。

**风险**：默认凭据是**全网皆知的密码**。在「公网访问」开启或宿主机端口可达的窗口期内，任何人都能在管理员改密之前抢先登录并接管面板。参考项目自己也为此加了补救——开启公网访问时强制完成安全初始化并撤销既有 API Key，但那是事后补救，窗口期依然存在。

---

## 决策

**1. 服务启动时检测是否已初始化；未初始化则生成一次性 bootstrap 令牌，打印到控制台日志。**

```
================================================================
  系统尚未初始化。请访问面板并使用以下令牌创建首个管理员：
  bootstrap token: 8f3c...  (仅在本次运行有效)
================================================================
```

**2. 初始化接口仅在「系统中不存在管理员」时可用。**

- `GET /api/v1/setup/status` — 公开，返回是否已初始化（供前端决定跳转）；
- `POST /api/v1/setup/admin` — 公开，需携带 bootstrap 令牌，创建首个管理员。

**3. 创建成功后令牌立即失效；一旦存在管理员，初始化接口永久返回「已初始化」并拒绝执行。**

判定口径为「是否存在 `role = admin` 且未被软删除的用户」，每次请求实时查库，不缓存。

**4. 令牌只存内存，随进程重启重新生成。**

未初始化状态下的重启生成新令牌属预期行为；已初始化后不再生成任何令牌。

**5. 初始化行为记入审计。**

记录来源 IP、时间与结果（**不记录令牌本身**）。

---

## 理由

| 选择 | 理由 | 备选与否决原因 |
|---|---|---|
| 控制台一次性令牌 | **无默认凭据**，且读取服务日志等价于拥有服务器访问权——这正是「谁有权初始化」的合理判据 | 默认密码：全网皆知的凭据，存在抢先登录窗口；纯 Web 初始化：第一个访问者即成为管理员 |
| 令牌随重启重新生成 | 未初始化状态下重启属于正常操作（如调整配置后重启），不应要求用户重新走部署流程 | 令牌持久化到数据库：多一份长期凭据，且已初始化后还要清理 |
| 实时查库判定「是否已初始化」 | 该判定是**安全边界**，缓存或标记位出错会导致初始化接口被再次打开 | 存标记位：多一处状态需要维护一致性；启动时判定一次：进程运行期间状态可能变化（如外带脚本创建了管理员） |
| 创建后自动建立会话 | 用户刚刚用令牌证明了身份，再要求登录一次是纯粹的摩擦 | 跳转登录页：多一步且无安全收益 |

---

## 后果

**正面**

- 不存在默认凭据，消除了「首次部署到改密之间」的接管窗口；
- 初始化者必须能读取服务日志，天然限制了可达范围（远程扫描者拿不到令牌）；
- 与 `f-1-01` 已定义的分级语义一致。

**负面 / 代价**

- **容器化部署需要查看日志才能初始化**（`docker logs <container>`）——比固定账号多一步，但这一步正是安全性的来源；
- 令牌出现在日志中，因此**日志文件的访问权限等同于初始化权限**，需在部署文档中说明；
- 若用户遗忘了令牌且未初始化，需重启服务获取新令牌。

**约束**

- 已初始化后，`/api/v1/setup/*` 的写操作必须**无条件拒绝**（不能仅靠前端隐藏）；
- 令牌比较必须使用常量时间比较，避免被计时推断；
- 审计中**不得记录令牌原文**。
