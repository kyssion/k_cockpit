# 0011. mock 增加电源生命周期的最小状态

- 状态：Accepted
- 日期：2026-09-30
- 关联：[`0007-mock-agent-first.md`](0007-mock-agent-first.md)（本 ADR 修订其实现口径的一处）· `internal/agent/mock.go`

---

## 背景

ADR-0007 确定「mock 只负责有返回值，不模拟执行行为」，mock 实现据此完全不维护状态：`OpVMStatus` 恒返 running，`vm.create` 结果只含 UUID。

这在演示环境（mock 运输层 + 预置节点）暴露出两处自相矛盾：

1. **创建后永远「状态未知」**：创建执行器的纪律是「状态以 agent 返回为准，拿不到不猜」，而 mock 的创建结果不带状态，新建虚拟机的投影停在 unknown。
2. **开机被自己的投影拒绝**：用户把新建（投影「已关机」）的虚拟机点「开机」，实时状态探测（`OpVMStatus`）恒返 running，请求被「虚拟机当前为运行中，无法执行开机」拒绝——与列表显示直接矛盾。「先关机再开机」的流转在 mock 下永远走不通。

mock 源码注释将此归因为「ADR-0007 明确不做」，属于**过度引申**：ADR-0007 排除的是**行为模拟**（耗时、进度推进、失败注入、离线与上报），并未禁止让各操作的返回值互相自洽。

## 决策

mock 维护一份**电源生命周期的最小状态**（虚拟机名 → 状态值，内存 map，`sync.Mutex` 守护）：

| 操作 | 之后的状态 |
|---|---|
| `vm.create` / 模板克隆 | stopped |
| `vm.start` | running |
| `vm.shutdown` / `vm.poweroff` | stopped |
| `vm.reboot` / `vm.reset` | running |
| `vm.delete` | 移除条目 |
| `vm.status`（探测） | 读表；mock 没见过的虚拟机沿用历史行为视为 running |

**仍然不做的事**（ADR-0007 的排除范围不变）：不模拟耗时与阶段时长变化、不注入失败、不模拟离线与心跳异常、不为磁盘/网络/快照等领域对象维护状态。

## 理由

| 选择 | 理由 | 备选与否决原因 |
|---|---|---|
| 最小电源状态表 | 电源生命周期是 M2 起的核心演示链路（ADR-0007 自己的背景一节就写着「建 VM → 开机 → 控制台 → 关机 → 删除」），自洽的返回值是它的前提 | 维持恒返 running：演示中「开机被拒、状态永远未知」，比没有演示更伤 |
| 未见过的虚拟机默认 running | 既有测试（直接插库构造 running 投影再验证拒绝路径）全部保持绿色，语义零漂移 | 默认 stopped：大量既有用例翻红，且「探测未知机器报关机」的语义同样存疑 |
| 新建 ADR 而非修改 0007 | ADR 只增不改是仓库纪律；本决策是对实现口径的修订，值得留痕 | —— |

## 后果

- 正面：创建/开机/关机/再开机的完整流转在 mock 下自洽；新建虚拟机投影正确落「已关机」；状态机拒绝路径的验证不受影响。
- 代价：mock 不再是纯函数式「有问必答」——同一虚拟机的同名探测在不同操作序列后返回不同值。需要确定性的测试用全新的 `NewMockClient()`（现状已然如此）。
- 边界：重启 mock（服务重启）后状态清零，虚拟机投影可能与 mock 内存态短暂不一致——投影的下一次真实操作会重新收敛，与「投影是缓存」的既有定位一致。
