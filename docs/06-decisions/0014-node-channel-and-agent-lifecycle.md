# 0014. 节点间通道与 agent 生命周期（待决议题）

## 背景

M5 收口时剩下五组能力，共同点是**不能靠写代码解决**：它们要么要求节点之间建立新的信任关系，要么要求新增第三方依赖，要么要求真实双机/制品分发环境才能验证。把它们混在功能待办里会诱导「先写个大概」，而这类能力的半成品比不做更危险（历史教训见 0013 的 mock 兜底与「假成功」）。

本 ADR **只登记议题、约束与前置条件，不接受任何实现**。每项开工前需独立新建 Accepted ADR，并具备对应的验证环境。

## 待决议题与候选方案

| 议题 | 现状 | 候选 | 前置条件 |
|---|---|---|---|
| live 热迁移 | 因 libvirt 对等连接需节点间互信凭据、与 0005「控制面不持有宿主机登录凭据」冲突而诚实阻断（offline / warm 可用） | A 控制面私有 CA 签发**专用传输证书**，节点间直连 mTLS；B 受限 SSH 指纹登记（需重新解释 0005 的边界）；C 继续阻断 | 需明确「专用传输证书 ≠ 宿主机登录凭据」；真实双节点验收 |
| 跨节点 relay | 编排与两侧执行器已在同机双 agent 等效回放验证；控制面拉源 staging 分片再回放目标的循环未实现 | 复用导出 / 分片上传通道，控制面只中转不落盘 | **真实两台宿主机**；同机共享 libvirtd 的伪影必须排除 |
| 证书续期 / 吊销 | 客户端证书长期有效，无续期 RPC、无 CRL / OCSP、无到期告警 | A 新增 `RenewCert` RPC（proto 变更 + 缩短有效期 + 吊销列表）；B 复用一次性 enroll 令牌重新签发；C 维持长期证书但加到期告警 | A 需要协议版本协商（现为 1）与证书轮换演练；B 需要运维流程 |
| agent 自动升级 | 无升级代码；规模化后只能人工逐台替换 | A 控制面分发签名制品 → agent 校验 → 原子替换 → systemd 重启 → 失败回滚；B 交给外部配置管理 | 制品签名与校验、版本兼容矩阵、回滚演练；`release.yml` 已先产出多平台制品 |
| GeoIP 来源地区 | 已诚实阻断、不引入依赖：端口转发 `allowed_regions` 从对外契约移除（历史列保留），防火墙三个可写 `geoip_regions` 的入口明确拒绝（节点侧无消费方），前端移除无效输入 | A 引入 GeoIP 库与离线数据库（许可证、数据更新、体积）；B 节点侧 `xt_geoip`；C 维持阻断 | **新增第三方依赖必须先说明理由并获确认**（`AGENTS.md` §5 红线）；数据源与更新策略；历史数据需人工核查 |

## 决策（提议，尚未生效）

1. 五项均维持「未实现」状态，不以占位代码、假成功或隐藏开关伪装交付。
2. 优先级：先解决**凭据边界**（live / relay 共用的节点间通道），再解决**agent 生命周期**（证书与升级共用的制品信任链），GeoIP 单独按依赖准入流程评估。
3. 每项开工前各自新建 Accepted ADR；本 ADR 在被取代前不作为实现依据。
4. 与本批并行、但不需要新决策的工作已另行落地：PostgreSQL 单实例锁、tag 触发的发布制品流水线（只出制品不部署）。

## 理由

- 0005 的安全边界是本项目的核心取舍，任何「节点间互信」方案都必须先说清凭据由谁持有、如何吊销，否则等于绕回「面板被攻破 = 全部宿主机 root」。
- 0013 之后开发与 E2E 都依赖真实 agent；没有双机环境与制品分发链路时，live / relay / 自动升级的验收结论不可信。
- 项目规则禁止擅自引入依赖；GeoIP 的数据源许可与更新频率是产品决策，不是编码问题。

## 备选方案

- **一次性写一份大 ADR 直接定稿**：否决——五项分属不同约束，混在一起会让任一议题无法独立验证与回滚。
- **先写代码再补 ADR**：否决——与「重大技术选型新建 ADR」及 0013 的教训冲突。

## 影响

- 正面：把「为什么没做」变成可评审的决策清单，避免重复讨论与半成品。
- 负面 / 代价：live 热迁移、跨节点 relay、证书续期、agent 自动升级、GeoIP 在决策前仍不可用。
- 需要的配套调整：双节点真机环境、制品签名与分发通道、协议版本协商策略，以及 `AGENT_ACCEPTANCE.md` 中对应验收项。
