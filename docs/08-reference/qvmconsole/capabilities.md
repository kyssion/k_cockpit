## 1. 信息架构

| 角色 | 菜单项（顺序即侧边栏顺序） |
|---|---|
| 管理员 | 工作台 / 虚拟机 / 模板管理 / 网络中心 / 公网 IP / 防火墙 / 存储池 / 我的存储 / 用户管理 / 节点管理 / 调度事件 / 任务中心 / 系统设置 / 安全中心 / API 文档 / 关于项目 |
| 弹性云用户 | 工作台 / 我的虚拟机 / VPC 网络 / 我的存储 / 任务中心 / 安全中心 / API 文档 / 关于项目 |
| 轻量云用户 | 在弹性云菜单基础上进一步收敛（隐藏"网络"分组，且无迁移/导出/锁定等）；网络由管理员分配，不可自助操作 |

> 菜单定义在 `web/src/config/nav.tsx`，分管理员与普通用户两套；轻量云再按路由守卫白名单收敛。**管理员同样拥有"我的存储"**（其个人存储空间），不只是用户侧能力。

**贯穿全局的两种云类型**：`elastic`（自助网络/存储/完整配额）与 `lightweight`（按单 VM 配额、菜单受限）。

**未迁移模块的处理约定**：尚未迁移的入口点击时 Toast 提示"将在后续迭代提供"，不产生死链。

## 2. 虚拟机管理（核心能力面）

### 2.1 列表页

| 能力 | 说明 |
|---|---|
| 实时刷新 | 进入即建 SSE（管理员 `/vm/sse`、用户 `/self/vms/sse`），断线 5s 重连；无独立"自动刷新"开关 |
| 缓存优先 | 从其它页返回先渲染本地缓存，再静默更新，避免转圈 |
| 双视图 | 表格 / 卡片，选择持久化 |
| 分组 | 全部 / 按状态 / 按模板 / 自定义；组头可折叠、组内全选、跨组多选 |
| 排序 | 名称、配置（资源使用）、IP 地址三列升降序 |
| 搜索 | 按 名称 / 备注 / 模板 / 标签 模糊过滤（客户端） |
| 标签 | 在列表内直接增删（回车或点加号、点标签上的关闭图标移除）；存于 libvirt 虚拟机元数据（缓存仅作投影）；每台 ≤20 个、单个 ≤32 字符 |
| 备注 / 分组 | 弹窗编辑；**分组为自由文本且可在编辑弹窗中直接新建**，"自定义"分组视图按分组聚合；备注与分组同属随 VM 保存的元数据（与标签一起通过编辑接口提交） |
| 资源进度条 | 配置列下实时 CPU / MEM 百分比；非运行态灰条 + 状态标注 |
| IP 直显 | 列表接口带 `include_ip=1`，未分配显示"未分配" |
| 批量电源 | 开机 / 重启 / 关机 / 强制断电 / 删除（危险操作二次确认，含"有锁定机"提醒） |
| 维护模式 | 维护模式下页面虚化并弹提示 |

**"更多"菜单**（按角色与云类型裁剪）：重置（仅暂停态）/ 重启 / 强制断电（仅运行态）/ 编辑备注 / 编辑分组 / 制作模板 / 导出 / 重装系统 / 迁移 / 转为独立虚拟机 / 启动或关闭救援系统 / 锁定或解锁 / 删除。

**电源 loading 状态语义**（值得逐条对照）：
- 开机、关机、强制断电：依赖 SSE/HTTP 刷新后的**状态变化**解除 loading；
- 重启、重置：**终态可能不变**，接口确认后立即解除，并额外触发一次静默刷新；
- 关机指令下发成功但状态仍为 `running` 时，行内**只保留"强制断电"**，隐藏其余操作。

### 2.2 创建

**四种创建方式**：ISO 镜像安装 / 模板快速克隆（含批量、原生链式）/ 导入已有磁盘（qcow2、raw、vmdk、vhd(x)、img 自动转换）/ 导入 OVF-OVA 虚拟机包。

**向导步骤**：创建方式 →（虚拟机包）→ 基础信息 → 硬件规格 → 存储介质 → 网络设置 → 系统配置 → 高级选项 → 硬件直通（仅管理员）→ 确认信息（全量摘要 + 缺失项汇总时禁用提交）。

**配置维度**：

| 分区 | 维度 |
|---|---|
| 基础 | 名称（字母数字短横线、≤63、唯一，支持"随机生成"）、批量数量、备注（限 200 字并显示计数）、系统类型（**Linux · Windows · 其他**，卡片副标题分别为 Ubuntu/CentOS/Debian、Server 2022/2019/11、FreeBSD/自定义）/ 系统版本（可搜索）、导入初始化、模板与凭据（用户名/密码/主机名） |
| 硬件 | vCPU（1–32）/ max_vcpu / 内存 / 内存热添加 / CPU 限制（CFS 带宽）/ CPU 拓扑（自动·宿主默认·自定义 插槽+核心）/ CPU 亲和性 / 虚拟化引擎（KVM·QEMU）/ 架构（x86_64·aarch64·riscv64）/ 机型 / 引导方式（BIOS·UEFI·UEFI+安全引导）/ 显示设备（VirtIO·VGA·VMVGA·QXL·Cirrus·ramfb·none）/ Watchdog（i6300esb·iTCO） |
| 存储 | 存储位置 / 磁盘格式（QCOW2·RAW）/ 驱动（VirtIO·SCSI·SATA·IDE）/ 系统盘（10–2000GB，按 OS 给建议值）/ 额外数据盘（独立大小·格式·驱动·IOPS）/ IOPS（总量 **或** 读写分离，**两者互斥**，0=不限）/ 多 ISO / 软盘 |
| 网络 | 网卡型号（VirtIO·e1000e·rtl8139）/ 多网口（每口：交换机 + 安全组 + 型号）/ 端口安全允许地址（IPv4/IPv6） |
| 系统 | 引导顺序（拖拽排序）/ 开机自启 / 启动冻结 |
| 高级 | 开发者选项（APIC·PAE）/ RTC（UTC·本地时间·自定义偏移 + 起始日期）/ QEMU Guest Agent / SMBIOS 类型 1 / 首次重启模式（正常·宿主冷启动，解决 Sysprep 黑屏）/ SPICE / 嵌套虚拟化 / KVM 隐藏 / vendor_id / direct boot / Domain XML 编辑 |
| 直通 | PCI 设备（GPU / NVMe / 网卡）；单张直通 VGA 自动 `x-vga=true` |

**联动规则（前端与后端各一份）**：
- Windows（ISO 选择或系统类型判定）→ UEFI + SATA 磁盘 + e1000e 网卡；
- `i440FX + Windows + UEFI` → **强制 BIOS**（否则卡在 TianoCore 固件画面）；
- ARM（aarch64）→ 强制 `virt` 机型 + UEFI + ramfb 显示；
- 选择 ISO → 自动补系统类型/版本/最小磁盘，首个 ISO 为主安装盘并把 cdrom 提前；
- 切换模板 → 带出模板元数据中的 vcpu/ram/disk/bus/nic/video/拓扑/重启模式；Windows 模板固定 `administrator`。

**其他创建期规则**：批量创建自动计算总资源并校验配额；提交前做 CPU 亲和性格式校验与密码泄露检测；批量时密码留空则每台自动生成。

### 2.3 详情页

- **Hero 三卡**：① 状态卡（状态图标 + 运行时长 + 电源操作 + 锁定/救援/重装/备注）② 资源卡（CPU/内存计量条、网络/磁盘 IO、配置摘要）③ VNC 截帧预览卡（每 20s 刷新，可开独立窗口）。
- **标签页**：系统信息 / 快照管理 / 网络管理 / 定时任务 / VNC 控制台 / SPICE 控制台 / 编辑（惰性挂载）。
- **系统信息**：CPU·内存（动态内存提示）·PCIe 热插槽用量（余量 ≤1 警告）·系统盘缺失警告·操作系统·机器类型·模板来源·备注·连续运行时长；**登录凭证**（用户名/密码显示与复制、离线重置密码）；**虚拟机 IP**（按网口汇总 IPv4/IPv6，多来源解析）；**公网 IP**（未配置隐藏）；VNC 端口 / 网络接口 / 显示设备；高级设置（开机自启·启动冻结·APIC·PAE·Guest Agent 状态·CPU 限制·CPU 亲和性·内存策略）；磁盘 IOPS 限制表。
- **网络管理**：四个子标签——端口转发（**开通时会自动把当前虚拟机 IP 绑定为静态地址，避免 DHCP 变化导致转发失效**）/ 静态 IP 与 DHCP 租约 / 运行状态（管理员）/ 网络诊断与抓包（管理员）。
- **定时任务**：一次性 / 每天 / 每周（多选星期）；动作 开机·关机·删除虚拟机。
- **VNC**：状态 / 开启（可设密码，需重启生效）/ 关闭 / 修改密码（即时生效）/ 对外暴露（高风险确认 + 重启生效）；独立窗口含 Ctrl+Alt+Del、常用组合键、发送文本、粘贴密码。
- **SPICE**：状态（未开启·仅本地·已对外暴露）/ 开关 / 改密 / 对外暴露（联动宿主防火墙）/ `.vv` 连接文件下载。
- **监控图表**：CPU / 内存 / 网络 / 磁盘 IO 四图，实时（SSE 驱动）与历史（时间范围）双模式；磁盘 IO 支持 **IOPS ↔ 吞吐量**一键切换。

**实时同步语义**（可直接借鉴的交互设计）：
- 详情 SSE 每 3s 推送全量；进入页面即推一次；
- **失焦 10s 自动断开**、重新聚焦立即重连，并清空网络/磁盘速率的增量基准（避免跨失焦累计值污染瞬时速率）；
- 当前可见标签才拉附属数据；配置类区块用"**配置签名**"区分"资源统计心跳"与"配置真变化"，仅后者重建表单；
- 编辑中的未提交输入（磁盘 IOPS 草稿、VPC 选择）不会被后台同步覆盖。

**IP 解析与降级**：接口 IP 依次尝试 QEMU Guest Agent → DHCP 租约 → 静态绑定 → ARP → `virsh domifaddr`；Agent 连接失败后同一 VM **等待 30s 再重试**，避免详情页刷新持续向 libvirt 写重复错误；等待期间用其余来源解析，不误报为网卡/OVS 故障。IP 为空时给出"未配置 Agent / 已配置未连接 / 已连接但无 IP"三种可执行提示。

### 2.4 编辑

**选项卡**：基础配置 / 磁盘与驱动器 / 启动与安全 / 网口管理 / 硬件直通（仅管理员）/ 高级设置。

**运行态可改矩阵**：

| 项 | 运行态 | 说明 |
|---|---|---|
| CPU | 仅当启用热添加，且只能增加（下限=原始值） | |
| 内存 | 下限=原始值，禁止缩小 | |
| 机型 / 引导方式 / 网卡类型 / 显示设备 / SPICE / CPU 拓扑 | ✗ 须关机 | |
| 直通设备 | ✗ 须关机 | 修改前提示需关机 |
| 磁盘扩容 / IOPS | ✓ 可热改 | 由 libvirt 同时更新运行态与持久化配置 |
| 磁盘驱动类型切换 | ✗ 须关机 | |

**提交方式**：加载时捕获表单与磁盘 IOPS 快照，保存时**只发送变化字段**（差异提交），避免无谓的 XML 重写。

**网口管理归属规则**：管理员可管理全部虚拟机网口；弹性云用户可自助管理本人虚拟机的**附加网口**（仅限本人的非系统交换机），主网口统一在 VPC 绑定中管理；轻量云不可自助；网口级速率限制仅管理员可见。

### 2.5 电源与生命周期

- 电源操作：开机 / 关机（优雅）/ 重启 / 强制断电 / 重置（仅暂停态）。
- 开机前置修复：改 `on_reboot=destroy`、清理不完整 `backingStore` XML 以规避 AppArmor 拦截、校验 UEFI NVRAM 文件存在。
- **端口安全开启时**：先以 `--paused` 启动 → 装策略 → 再 resume，避免恢复瞬间无防护。
- **暂停类型要区分**：普通暂停可"继续启动"；QEMU `internal-error` 暂停需提示重置，不能当普通暂停处理。
- 删除语义：可选"删除磁盘"或"把磁盘转移到我的存储"；批量支持；锁定机有专门提醒。

### 2.6 快照

| 场景 | 策略 |
|---|---|
| 关机状态 | 内部快照 |
| 运行中 + 含内存 | 内部快照（可选择先 suspend → 创建 → resume） |
| 运行中 + 不含内存 | **外部快照**（`--disk-only`） |

- 配额以"已用/上限"徽标呈现，达上限禁用创建；支持"删除全部快照"。
- **外部快照与含子快照的恢复/删除有专门提示文案**。
- UEFI NVRAM 需修复时自动弹确认，可一键修复后继续创建。
- 内部/外部快照的能力差异（恢复速度、适用场景）在界面上有明确说明。
- 挂载宿主机共享目录（9p/VirtFS）时不允许创建含内存的内部快照。

### 2.7 磁盘与设备

| 能力 | 关键约束 |
|---|---|
| 磁盘热插拔 | q35 机型需空闲 PCIe 根端口；**槽位耗尽自动降级 virtio-scsi** |
| 磁盘扩容 | 仅允许扩大；可勾选"进来宾自动扩容"（普通分区与 LVM） |
| IOPS 限制 | 总量与读写分离互斥；保存时统一提交 |
| 光驱 / 软盘 | 插入 / 弹出 / 移除 / 新增；驱动类型可选 SCSI·SATA·IDE·USB，**运行中固定使用可热插的 SCSI**；Q35 隐藏 IDE |
| PCI 直通 | 需先加载 vfio 并绑定 `vfio-pci`；修改须关机 |
| 挂载已有磁盘 | 管理员支持绝对路径导入 |
| **宿主机目录共享** | 把宿主机目录以 **9p VirtFS** 共享给虚拟机：需指定 `tag`（来宾挂载点标识）、`security_model`（`mapped` / `passthrough`）与只读开关；支持查询已挂载列表并卸载 |
| 离线扩容 | FnOS（`resize2fs`）/ Windows（`ntfsresize`）+ 恢复分区"备份→删除→扩展→重建→恢复→修复" |

### 2.8 控制台

- **VNC**：默认**仅监听 `127.0.0.1`**，只能通过面板 WebSocket 代理访问；需要直连时再手动"对外暴露"；独立窗口支持常用组合键、发送文本、粘贴已保存凭据。
- **SPICE**：**不经面板代理**，客户端直连 QEMU 端口；面板提供状态/开关/改密/暴露与 `.vv` 文件下载。
- 显示设备设为 `none` 时，详情页隐藏 VNC/SPICE 入口。

### 2.9 迁移

- **方式**：热迁移（运行中，业务不中断）/ 冷迁移（关机后复制磁盘）。
- **预检项**：平均带宽、脏页速率、脏页占比、CPU 限制、磁盘检查、backing 检查、端口转发、目标同名 VM、存储余量、网络匹配。
- **评估口径**：先做线路测速（平均带宽），再读 libvirt dirty-rate 并计算"脏页速率 ÷ 平均带宽"；同时尝试读 `kvm_stat` 的 KVM 页错误率，`kvm_stat` 不可用时仅告警、不阻断评估。
- **阈值**（代码常量）：比值 ≥ **0.20** → 强制启用 CPU 限流（默认限到 **50%**，可配置）；比值 ≥ **0.50** → **直接阻断**热迁移并给出"脏页速率 / 平均带宽 / 占比"的原因文案。
- **本机磁盘迁移**：`virsh blockcopy` 热迁移 / 稀疏复制 + rebase 冷迁移；链式磁盘先预创建 overlay。
- **跨节点约定**：目标节点 SSH 用户必须为 `root`；迁移完成后调目标面板接管接口补齐 NVRAM、用户、VPC 绑定、凭据与端口转发。

### 2.10 重装 / 救援 / 锁定 / 导出

| 能力 | 语义 |
|---|---|
| 重装系统 | 高风险二次验证；同一 VM 只允许一个进行中；**保留硬件配置、数据盘、主网口 VPC 绑定**；仅替换系统盘并按新模板初始化；失败还原原 XML 与备份盘 |
| 救援系统 | 断电 → 记录原配置 → 盘改 SATA、网卡改 e1000e、挂救援 ISO、引导改 `cdrom,hd` → 开机；退出时逆操作还原 |
| 锁定 / 解锁 | 业务软锁：禁删除、禁移动磁盘，关机仅提示；解锁需二次验证 |
| 导出 | QCOW2 系统盘 或 标准 OVA（要求关机，系统盘固定、数据盘可选）；结果计入用户存储配额 |
| 转为独立虚拟机 | 仅管理员 + 链式克隆 + 关机态 |

### 2.11 来宾自动化与密码重置

- **密码重置**：运行中经 QEMU Guest Agent 在线改密；关机态走离线改密；默认自动选择路径；改密前做强度校验与泄露检测。
- **磁盘自动化**：新空盘自动分区格式化并挂载（Linux：ext4/XFS/Btrfs + 按 UUID 写 `/etc/fstab`（`nofail` 且更新前备份）；Windows：GPT + NTFS + 分配盘符并跳过系统/启动/EFI/恢复/只读卷）；已有数据盘自动识别挂载；单台与批量克隆的额外磁盘自动挂载。
- **系统盘扩容**：可勾选进来宾自动扩容（普通分区与 LVM）。
- **执行阶段可观测**：任务结果区分"宿主机阶段 / 来宾阶段"，宿主机成功而来宾失败时可单独重试；同一 VM 的磁盘自动化与密码重置串行执行。

### 2.12 监控

- **虚拟机指标**：CPU / 内存 / 磁盘 IO / 网络流量 / 运行时间；磁盘 IO 可切 IOPS 或吞吐量口径。
- **宿主机指标**：CPU / 内存 / 网络流量 / 磁盘 IO，且**可按物理网卡、物理硬盘分别查看**（支持"全部汇总"与"指定设备"两种模式）。
- **采集与展示解耦**：后台周期采集，列表与详情只读缓存，避免请求路径直连虚拟化层。

## 3. 工作台与全局界面

### 3.1 管理员工作台

- **区块**：宿主机状态横幅 → 4 张统计卡 → 宿主机资源监控四图 → 最近虚拟机（5 台）。
- **宿主机状态横幅**：正常（青）与警告（琥珀）两态；警告触发条件为 CPU ≥90%、内存 ≥90%、存储剩余 <10GB、任一可写挂载点可用空间 <10GiB，**以及"未配置 SMTP"**（与负载原因分句并列）。
- **"理论最大量"双进度条**（有设计含量的口径，值得照抄思路）：
  - CPU 理论值 = Σ(运行中虚拟机 vCPU) / 宿主机核数；
  - 内存理论值 = (系统当前占用 + Σ(运行中虚拟机最大内存)) / 宿主机内存，其中系统基线 = 宿主机已用内存 − 运行中虚拟机当前分配内存；
  - 磁盘理论值 = Σ(全部虚拟机磁盘容量) / 宿主机磁盘；
  - 已停止 / 暂停 / 迁移中的虚拟机不计入 CPU 与内存理论值；磁盘不受运行状态影响；
  - 同一轨道内"当前使用量"（上层遮罩）与"理论最大量"（下层斜纹）叠放，理论值可超 100%，轨道按 `max(当前, 理论, 100%)` 归一化并画 100% 刻度线。
- **内存卡片 KSM / zRAM 体现**：开启 KSM 时显示"KSM 节省 xx"（悬停展开 KSM/zRAM 明细）；开启 zRAM 时进度条增加第三条琥珀斜纹区段表示进入压缩交换的阶段；未开启时整块自动隐藏。
- **CPU / 内存卡片"硬件详情"折叠区**（默认收起，收起即卸载面板、停止请求）：
  - CPU：型号 + 插槽/物理核心/线程数 + **每核使用率色块网格**（按 <10%/<40%/<70%/<90%/≥90% 五档着色），展开期间每 3s 轮询；
  - 内存：已插/总插槽 + 每根内存条（插槽位置/容量/类型·频率·厂商），数据源 `dmidecode`；SMBIOS 无数据（常见于虚拟机/部分 ARM）时返回中文说明并正常降级。

### 3.2 普通用户工作台

- **区块**：资源总览 5 卡（CPU / 内存 / 实例 / 磁盘 / 本月时长，配额为 0 显示"不限"）→ 配额详情 3 个折叠分类（计算与实例 / 存储 / 网络资源）→ 我的虚拟机资源追踪。

### 3.3 登录页（多阶段流程）

登录不是单步，按后端返回的 `stage` 切换右侧卡片：

| stage | 界面 | 要点 |
|---|---|---|
| `force_password_change` | 强制改密弹窗 | 仅写入临时 token（后端只放行改密/登出白名单接口）；新密码经本地弱密码快检 + 泄露检测；成功后旧 token 因 `security_updated_at` 更新立即失效，**前端用新密码自动重新登录** |

| `success` | 进入系统 | 应用会话并写入用户 Store |

其他：必须勾选用户协议才能点登录；密码可见性切换；"返回登录"放弃本次流程回到登录表单。

## 5. 值得对照的关键设计维度

实现同类能力时，建议按下面这些"维度清单"逐项定方案（它们决定功能边界，比具体实现更重要）：

1. **并发模型**：重操作是否统一入任务队列；是否需要按资源（VM/存储/迁移）加锁；同类型任务是否允许并行。
2. **实时通道**：列表、详情、任务、宿主指标各用一条通道；推送间隔、心跳、会话校验、重连与失焦策略。
3. **状态同步**：VM 列表/详情用缓存投影 + 增量推送，还是每次直查虚拟化层；缓存如何对账。
4. **配置维度与默认值**：创建表单的字段全集、按 OS/架构/模板的推荐与强制规则、批量与单台的差异。
5. **运行态约束矩阵**：哪些项可热改、哪些须关机；前端禁用与后端校验必须两份。
6. **提交粒度**：编辑是否走差异提交；如何避免覆盖用户未保存输入。
7. **失败与回滚**：每个长流程（创建/克隆/迁移/重装/导入）的失败点与回滚范围，取消算不算失败。
8. **能力探测**：哪些功能依赖宿主机/虚拟化层能力，是否必须先预检、能力不足时拒绝还是降级。
9. **配额与归属**：配额维度、统计口径（增量还是快照）、超限处置（拒绝还是自动收敛、转只读还是自动关机）。
10. **安全等级**：哪些操作需要二次验证；令牌分级与会话失效策略；日志脱敏范围。
11. **依赖分层**：每项能力依赖哪些系统命令/来宾侧软件，缺失时是"整功能不可用"还是"降级"——参考项目为此专门维护了运行时依赖清单（见 §6）。
12. **功能生命周期**：参考项目自身处在**前端重写 + 功能裁剪**过程中，同一能力可能存在"旧文档描述 / 新实现移除"的冲突，实现前必须确认目标版本是否真的要它（见 §7）。

> 这些是**对照清单**，不是我们的设计结论；`k_cockpit` 自己的选型与方案写在 [`../../02-architecture/`](../../02-architecture/) 与 [`../../07-specs/`](../../07-specs/)。

**第三条经验：配置项存在 ≠ 能力存在。** 判断某功能是否真的可用，必须找到**读取该配置的代码路径**；只看 `.env`、安装脚本或设置页的出现，会把"残留配置项/未实现功能"当成可参考的能力。同理，`docs/` 里描述的功能也应以"能否在代码里找到落点"为最终依据。

**第四条经验：仅存在于站点手册的功能点，引用前必须回代码验证。** 本文档第二轮整理时曾把手册里的"端口转发 TCP 探测验证连通性"当作现有能力写入，第三轮代码检索发现它随"建站扫描"一起被移除了——**手册里的功能描述一律按"待验证"处理**，验证方式是"前端有无入口 + 后端有无实现 + API 是否存在"三者齐全。

**另一类需要注意的差异**：参考仓库是**上游 fork**（上游 `QVMConsole/QVMConsole` 只合并后端，前端为本仓库自研），且**全仓库没有测试代码、后端无 lint 配置**（`AGENTS.md` 明确"本项目没有测试代码"）。这意味着它的实现结论**缺少回归保障**，我们借鉴时不能把"它现在这样写"当成"这样是对的"。

| VNC 控制台 | 显示"VNC 已开启 / 认证：none (Sub: none) / 端口：5900 (ipv4)"；打开独立窗口、设置密码、开启对外暴露、关闭 VNC |
| SPICE 控制台 | "SPICE 协议（外部客户端）" 状态 + 开启 SPICE |
| 编辑 | 子选项卡 基础配置 / 磁盘与驱动器 / 启动与安全 / … + **保存修改**（差异提交） |

**端口转发的两条页面文案**（值得照抄的设计说明）：① "开通端口转发时，系统将自动把当前虚拟机 IP 绑定为静态地址，**避免转发目标在 DHCP 变化后失效**"；② "端口转发用于从外网的访问流量转发到虚拟机……请确认您暴露到公网的服务已完成必要的安全加固"。

### 8.4 结论

- 两轮页面实测**均未发现新的能力域**，产出全部是"字段、文案、操作项、状态呈现"级别的补充，说明能力面已收敛。
- 过程中修正了两处**由站内手册或我自己口头总结引入的偏差**：① 端口转发"TCP 探测"（已移除，第二份经验）；② "网络中心 5 个 Tab"（实际 4 个，端口镜像属概览内区块）。
- 方法论提示：**同一个功能的"层级归属"（是 Tab 还是区块、是必填还是条件显示）最容易出错**，写文档时应以"实际点击路径"为准，而不是以页面里出现的文字先后顺序推断。
