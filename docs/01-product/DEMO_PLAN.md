## 1. 目标与交付策略

**目标**：一套可以给外部观众完整演示的「页面 + 控制面服务端」，覆盖管理侧主要能力面。观众看到的是真实运行的系统——真实的登录、权限、任务、审计、配额——而不是静态原型。

**三条交付策略**（本文的执行口径）：

1. **页面与服务端全真**：数据模型、校验、任务状态机、权限归属、审计、高风险二次验证、配额判定一律真实实现，不因为演示而绕过控制面逻辑。
2. **agent / 虚拟机 / 远程交互一律 mock**：按 [ADR-0007](../06-decisions/0007-mock-agent-first.md) 执行——mock 只返回结果、不模拟行为（不做耗时、进度推进、失败注入），业务代码只依赖 `agent.Client` 接口、不得感知 mock，接口按需扩展。
3. **一项一闭环**：每个条目都是「前端 + 后端 + 测试」同一轮交付，不留半成品页面。开工前按 [`GAP_CLOSURE.md`](GAP_CLOSURE.md) §3 的硬规则核对代码，核对结果写进条目。

**演示期明确不做**：真实 agent（gRPC/mTLS/宿主侧领域操作）、模拟 agent 行为的假 agent、跨节点真实数据搬运、异常分支的专项验证（见 §6）。

| **G-51** | VM 详情 → 网络管理 → 端口转发 | **转发与静态地址的联动（或至少提示）** | `internal/vm/network_write.go` 的 `BindStaticIP` 与端口转发是两条独立链路，既无联动也无提示。对方把这条写成页面文案："开通端口转发时，系统将自动把当前虚拟机 IP 绑定为静态地址，避免转发目标在 DHCP 变化后失效" | S（提示）/ M（真联动） |
| **G-52** | 我的存储 → 挂载管理；系统设置 → 存储管理 | **用户存储维护可视化** | `storageExtraApi.trim` 有，但"镜像文件挂载点 / 自动定时回收开关 / 执行结果"没有页面落点 | S |
| **G-53** | 安全中心 → API 凭证 | **一次性动作令牌无前端入口** | 后端 `POST /api/v1/action-tokens` 已注册（`internal/router/router.go:573`），`web/src/api/apikey.ts` 只有 get / create / revoke | S |
| **G-54** | 系统设置 → 基础设置 / 存储与网络 | **一批运营期设置项** | `自动分配` 全仓无命中；端口自动分配范围、端口转发持久化目录、OVS 网桥 / 出口网卡 / 网段前缀 / DHCP 范围 / 外网网卡 / 公网 IPv6 前缀检测周期，在 `internal/settings/spec.go` 均无对应 key | M |

**结论**：整块能力面已对齐——我们 36 个菜单页 / 46 条路由，对方 16 个菜单页。剩余缺口不在
「有没有这个页面」，而集中在三类：① 系统设置项覆盖面（对方设置页是一等公民，我们只有 22 个设置项）；
② 「非功能性但页面可见」的能力；③ 承诺与能力不一致。

#### 两处需要单独说明的

**G-49 不是「少一个功能」，而是「已经承诺出去、产物却不能用」。** 管理员在邀请面板复制到的
`/invite/<token>` 发给用户是打不开的——它是相对路径，脱离当前站点就没有意义。这与第三轮记录的
"文案承诺下载但能力不存在"是同一类：**功能闭环的最后一环断了**。修它不需要新能力，只需要一个
站点对外地址（配置项或环境变量），并把 `main.go:318` 那个空实现接上。

**G-46 不能直接照搬对方的单机语义。** 对方是"关掉所有运行中的虚拟机 + 停掉配置里的宿主机服务"，
因为面板就跑在那台机器上。我们是多节点控制面，全站维护应定义为**按节点逐个进入维护**并汇总结果，
而不是照抄一个"关掉全部"的开关——照抄会在演示环境里表现为"点了之后所有节点一起变灰，
但没有任何一台真的被关"。

#### 本批刻意不做

| 项 | 不做的理由 |
|---|---|
| 批量克隆并发可配置 | 现为 `const MaxBatchClone = 5`（`internal/vm/batch_clone.go:22`）且拒绝时把理由写进了报错。配置项化收益低 |
| 节点 SSH 双通道 + 9 项探测 | 架构差异：agent 未实现（ADR-0007），探测没有对象 |
| 会话指纹绑定 | **已实现且更强**：`internal/auth/session.go:253` 指纹不匹配会记 `session.fingerprint_mismatch` 安全事件 |

#### 排序建议

沿用 [`GAP_CLOSURE.md`](GAP_CLOSURE.md) §6 的排序依据（**不做会不会让人用不了系统** >
**不做会不会让人白买硬件** > **不做会不会让排查没有依据**）：

| 顺序 | 编号 | 理由 |
|---|---|---|
| 1 | G-49 | 唯一一个"已经承诺出去但产物不能用"的 |
| 2 | G-42 | 唯一一个"对方有开关、我们整层没有"的防护层，且是安全边界 |
| 3 | G-43 | 排障依据：libvirt / 命令执行这两类输出目前没有落点 |
| 4 | G-46 | 运维动作，且它的语义需要先由我们定义（多节点 ≠ 单机） |
| 5 | G-44 / G-45 / G-47 / G-48 / G-50 / G-51 | 打磨项，按演示观感排 |
| 6 | G-52 / G-53 / G-54 | 后端已有能力缺前端入口，或属运营深化 |

> **填这一批时的一条提醒**：不要照抄对方的设置项。
> [`capabilities.md`](../08-reference/qvmconsole/capabilities.md) §7 明确记着"配置项存在 ≠ 能力存在"
> （`KVM_DYNAMIC_MEMORY_*` 只有安装脚本写、基线代码里无人读）。上表每一项都回查了读取方，
> 将来新增时仍要先找到消费代码再认它是能力。

## 6. 演示期风险与口径（ADR-0007 的已知代价）

1. **异常分支未经验证**：agent 超时、离线、执行失败在 mock 下不可触发。演示脚本**不要**主动演示失败路径；观众问「失败怎么办」时，用架构回答（任务重试、降级告警、断连对账——设计已存在，只是未联调）。
2. **mock 返回形状是假设**：接入真实 agent 时需校准字段，业务代码零改动已由 ADR-0007 第 3 条保证；每个新增 agent 接口方法在实现时同步在规格中登记协议语义。
3. **数据说服力**：演示环境的监控图表、配额用量来自 mock/种子数据，需在演示口径上说明「数据为演示数据，链路为真实链路」。
