## 1. 目标与交付策略

**目标**：一套可以给外部观众完整演示的「页面 + 控制面服务端」，覆盖管理侧主要能力面。观众看到的是真实运行的系统——真实的登录、权限、任务、审计、配额——而不是静态原型。

**三条交付策略**（本文的执行口径）：

1. **页面与服务端全真**：数据模型、校验、任务状态机、权限归属、审计、高风险二次验证、配额判定一律真实实现，不因为演示而绕过控制面逻辑。
2. **agent / 虚拟机 / 远程交互一律 mock**：按 [ADR-0007](../06-decisions/0007-mock-agent-first.md) 执行——mock 只返回结果、不模拟行为（不做耗时、进度推进、失败注入），业务代码只依赖 `agent.Client` 接口、不得感知 mock，接口按需扩展。
3. **一项一闭环**：每个条目都是「前端 + 后端 + 测试」同一轮交付，不留半成品页面。开工前按 [`GAP_CLOSURE.md`](GAP_CLOSURE.md) §3 的硬规则核对代码，核对结果写进条目。

**演示期明确不做**：真实 agent（gRPC/mTLS/宿主侧领域操作）、模拟 agent 行为的假 agent、跨节点真实数据搬运、异常分支的专项验证（见 §6）。

## 4. 实施批次与完成标准

排序原则：**演示观感 × 依赖就绪度**。每批完成即达到一次「可对外演示」的状态，批次间无强阻塞。

| 批次 | 条目 | 完成标准（演示脚本可走通） | 预估档 |
|---|---|---|---|
| **Demo-1：创建与详情的纵深** | G-29、G-30、G-31 | 现场：创建向导演示 Windows 联动（自动 UEFI+SATA+e1000e）与高级维度 → 详情页看到截帧预览、登录凭据、公网 IP → 控制台发 Ctrl+Alt+Del | L |
| **Demo-2：多租户故事** | G-32、G-33 | 现场：切普通用户登录 → 工作台呈现配额 5 卡与资源追踪 → 超配额创建被拒 → 对运行中 VM 热扩内存（编辑矩阵） | M |
| **Demo-3：导入与迁移** | G-34、G-35 | 现场：上传一个 OVA → 解析预览 → 导入任务在任务栏推进 → 产物模板一键克隆；迁移预检演示脏页评估与 0.50 阻断 | L |
| **Demo-4：语义与打磨** | G-36、G-37 | 现场：定时删除任务触发二次验证；列表进度条实时跳动；关机中状态机表现正确 | M |

**依赖关系**：G-29 依赖表单矩阵机制（已有）；G-32 依赖 G-07 累计配额（已完成）；G-34 依赖我的存储分片上传（已实现，复用）；G-35 依赖迁移预检框架（已有）。批次内条目无相互依赖，可并行。

**与 [`ROADMAP.md`](ROADMAP.md) 的关系**：本规划调整的是 M2/M3 内的**执行顺序**（演示优先），不改变阶段目标与完成标志；条目落地时仍按各自 PRD 编号归属阶段口径。真实 agent 接入（节点纳管、宿主侧领域操作）仍归 [`ROADMAP.md`](ROADMAP.md) M2 §2.2 / M4 的既有安排，不被本规划提前。

## 6. 演示期风险与口径（ADR-0007 的已知代价）

1. **异常分支未经验证**：agent 超时、离线、执行失败在 mock 下不可触发。演示脚本**不要**主动演示失败路径；观众问「失败怎么办」时，用架构回答（任务重试、降级告警、断连对账——设计已存在，只是未联调）。
2. **mock 返回形状是假设**：接入真实 agent 时需校准字段，业务代码零改动已由 ADR-0007 第 3 条保证；每个新增 agent 接口方法在实现时同步在规格中登记协议语义。
3. **数据说服力**：演示环境的监控图表、配额用量来自 mock/种子数据，需在演示口径上说明「数据为演示数据，链路为真实链路」。
