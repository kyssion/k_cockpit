## 1. 背景与目标

### 1.1 背景

VNC 是虚拟机的「最后一条命脉」——网络不通、系统起不来时，控制台是唯一的操作入口。

但它的数据通路在既有架构里**没有定义**，且存在一个必须解决的矛盾：

> [`ADR-0005`](../06-decisions/0005-control-plane-node-agent-architecture.md) 规定控制面**不直连宿主机**，且宿主机**常位于内网 / NAT 之后**（控制面不保证能主动连入）；
> 而 qemu 的 VNC 监听在宿主机 `127.0.0.1:5900+`——**控制面没有任何合法路径直连它**。

因此本规格必须先定义通道路径，再谈功能。

### 1.2 目标

- 浏览器可**安全地**通过面板访问虚拟机控制台，无需在宿主机上开放 VNC 端口；
- 控制台**默认不对外暴露**（仅本机监听 + 经面板代理）；
- 支持独立窗口、常用组合键、发送文本、粘贴凭据、全屏；
- 详情页提供**截帧预览**（无需连接即可看到屏幕）；
- 控制台重依赖**不进首屏包**。

### 1.3 不做什么（范围外）

| 不做 | 归属 |
|---|---|
| SPICE 控制台与 `.vv` 文件 | F-2-09（P2，M4） |
| 串口 / 终端（xterm.js） | 属 §4.7 终端容器，后续按需 |
| 录像与回放 | 未在 PRD 中提出 |
| 多用户同时操作同一控制台的协作/抢占控制 | 见 §9 Q-009 |

## 2. 用户与场景

```text
作为 用户，
我希望 在浏览器里直接看到虚拟机屏幕并操作键盘鼠标，
以便 在系统无法远程登录时仍能处理问题。

作为 管理员，
我希望 控制台默认只在面板内部可达，
以便 不会因为开了控制台就在宿主机上暴露一个可被扫描的端口。
```

## 3. 功能描述

### 3.1 数据通路（本规格的核心）

```text
浏览器（noVNC，前端）
  ⇄ WebSocket ⇄ 控制面（鉴权 + 授权 + 会话绑定）
  ⇄ agent 反向长连接（流式转发，多路复用）
  ⇄ 宿主 127.0.0.1:<vnc_port>
  ⇄ qemu
```

**约定**：

- VNC 端口**默认仅监听 `127.0.0.1`**，宿主机不对外开放；
- 控制面到宿主机之间**复用 agent 通道**，不新建直连路径（[`ADR-0005`](../06-decisions/0005-control-plane-node-agent-architecture.md)）；
- 同网段且启用了 ADR-0005 第 2 条的「直连模式」时，可作为**性能优化**走直连，但**反向通道必须仍然可用**（否则该节点无法使用控制台）；
- 该路径要求 agent 通道支持**流式数据转发**（见 §5.2 对通道协议的补充要求）。

### 3.2 交互细节

与 [`FRONTEND.md`](../02-architecture/FRONTEND.md) §5.3.4 一致，要点：

| 环节 | 要求 |
|---|---|
| 详情页标签 | 「VNC 控制台」标签展示状态（未开启 / 仅本机 / 已暴露）、开关、改密、对外暴露、打开独立窗口 |
| 独立窗口 | 无主布局；工具条含连接状态、缩放自适应、`Ctrl+Alt+Del` 与常用组合键、发送文本、粘贴凭据、全屏 |
| 截帧预览 | 详情页「控制台预览卡」，每 20s 更新；**显示设备为 `none` 时隐藏该卡** |
| 未开启时 | 给出「开启 VNC」引导，而不是空白或报错 |
| 断线 | 自动重连并提示重试次数 |
| 懒加载 | noVNC 与终端等重依赖**不进首屏包**（[`FRONTEND.md`](../02-architecture/FRONTEND.md) §6.7） |

### 3.3 业务规则

| 编号 | 规则 |
|---|---|
| R-001 | VNC 端口**默认仅监听 `127.0.0.1`**；宿主机上不开放对外端口 |
| R-002 | 控制台流量**必须经控制面代理**（反向通道），控制面**不得**直连宿主机端口 |
| R-003 | 控制台的 WebSocket 连接**必须绑定已认证会话**；连接前的授权判定与详情页一致（[`f-1-06`](f-1-06-authorization.md)：他人 VM 返回 404） |
| R-004 | **对外暴露是高危操作**：必须走高风险二次验证（[`f-10-01`](f-10-01-high-risk-verification.md)），并明确提示「将向网络开放宿主机端口」；**默认关闭** |
| R-005 | VNC 密码**加密存储**，接口**不回传明文**；仅支持「设置新密码」，不支持「查看密码」 |
| R-006 | **粘贴凭据**（写入控制台）走独立的凭据读取路径，凭据值**不得**进入日志、审计正文与前端持久存储 |
| R-007 | 控制台会话与 VM 的映射关系由控制面维护：**一个 WebSocket 对应一个控制台会话**，关闭时释放转发资源 |
| R-008 | 控制台连接**超时与空闲断连**策略：窗口失焦或长时间无输入不主动断开（控制台常需长时间观察），但网络断开后按重连策略处理 |
| R-009 | 断线重连需**提示重试次数**，并允许用户手动重试；重连不得创建重复会话（先释放旧会话） |
| R-010 | 改密或切换暴露状态属**配置变更**，其中「对外暴露」需重启生效（提示用户），「改密」按 libvirt 的实际行为提示 |
| R-011 | 显示设备为 `none` 的虚拟机**无控制台**：详情页隐藏预览卡与相关入口，接口返回明确原因而非空数据 |
| R-012 | 控制台**不承载文件传输**（noVNC 的剪贴板文本除外）；大文件通过其他能力（如目录共享 F-5-06） |
| R-013 | 代理层**不得**把 VNC 流量写入日志或落盘；仅记录会话建立/关闭与异常事件 |
| R-014 | 同一虚拟机的控制台会话数**需要有上限**（避免资源耗尽），达到上限时明确拒绝并说明（§9 Q-009） |

## 4. 边界与异常

| 场景 | 触发条件 | 期望行为 |
|---|---|---|
| VNC 未开启 | VM 未配置 VNC | 详情页给出「开启 VNC」引导；接口返回明确状态而非错误 |
| 显示设备为 none | VM 无显示设备 | 隐藏预览卡与控制台入口；接口说明原因 |
| 节点离线 | agent 不可达 | 控制台不可用，提示「节点离线」；不建立连接 |
| agent 通道不可用 | 反向通道断开 | 同上；不尝试直连宿主机（R-002） |
| 控制台会话被占用 | 达到并发上限 | 拒绝并提示（含当前占用数） |
| 密码错误 | 用户输入的 VNC 密码不符 | 由 VNC 服务拒绝；前端提示「密码错误」，不泄漏宿主机信息 |
| 网络抖动 | WebSocket 断开 | 自动重连并提示重试次数；重连前释放旧会话 |
| 页面刷新 | 独立窗口重载 | 重新建立会话；旧会话由服务端超时回收 |
| VM 被删除或关机 | 控制台会话期间 | 会话结束并提示原因；不挂起资源 |
| 对外暴露后又被关闭 | 配置变更 | 端口收回；已有会话按配置变更策略处理（提示需重启生效） |
| 截帧失败 | VM 关机 / 无显示设备 | 预览卡显示占位与原因，不显示上一帧（避免误导为当前状态） |
| 截帧频率过高 | 多个页面同时打开 | 服务端按 VM 维度缓存短时截帧，避免重复向 agent 请求 |
| 非法订阅 | `tenant` 访问他人 VM 的控制台 | 返回 404（与详情页一致） |

## 5. 数据与接口

### 5.1 数据变更

| 实体 | 变更 | 说明 |
|---|---|---|
| `vm` | **复用** | VNC 端口等信息归入配置投影（[`DATA_MODEL.md`](../02-architecture/DATA_MODEL.md) §4.6） |
| `vm_credential` | **复用** | VNC 密码与来宾凭据的加密存储落点（§4.9） |
| `audit_log` | 复用 | **开启/关闭 VNC、改密、对外暴露**必须审计；控制台连接只记会话事件（不记内容） |

> **无需新增迁移**。

### 5.2 对 agent 通道的补充要求

本规格要求 agent 通道具备**流式数据转发**能力（在既有「领域操作 + 任务指令 + 进度流」之外）：

| 项 | 要求 |
|---|---|
| 多路复用 | 单条 agent 长连接上承载多个控制台流，互不阻塞 |
| 流标识 | 每个流有独立标识，与 VM 和控制台会话绑定 |
| 背压 | 前端消费慢时不得无限缓冲（内存风险），需有背压或丢弃策略 |
| 生命周期 | 会话关闭/超时/VM 变更时，两侧资源都必须释放 |
| 不落盘 | 转发的数据不写日志、不落盘 |

> **该要求已回填至 [`f-6-01-node-onboarding.md`](f-6-01-node-onboarding.md)**（协议能力范围），实现 agent 通道时按两处规格一并落实。

### 5.3 接口

登记至 [`API.md`](../03-api/API.md)：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/vms/:id/console` | 控制台配置与状态（是否开启、端口、暴露状态、显示设备） |
| PATCH | `/api/v1/vms/:id/console` | 开启/关闭、设置密码、切换对外暴露（暴露需二次验证） |
| GET | `/api/v1/vms/:id/console/screenshot` | 控制台截帧预览（服务端短时缓存） |
| GET | `/api/v1/vms/:id/console/ws` | **WebSocket**：VNC 流量代理（升级后为 VNC 协议） |

**要点**：

- 截帧接口需**短时缓存**（按 VM 维度），避免多页面同时打开时重复向 agent 请求；
- WebSocket 端点需在**连接建立时完成鉴权与授权**，不能只在 HTTP 阶段校验；
- 密码相关字段**只写不读**。

## 6. 非功能要求

| 类别 | 要求 |
|---|---|
| 安全 | 默认仅本机监听；必经代理；暴露需二次验证；密码加密且不可读；流量不落盘 |
| 性能 | 控制台重依赖不进首屏包；截帧按 VM 缓存；转发需有背压保护 |
| 资源 | 控制台会话数有上限；会话结束必须释放转发资源（避免长连接泄漏） |
| 可用性 | 断线自动重连并提示；未开启时给出引导而非报错 |
| 可观测性 | 会话建立/关闭、异常、上限触发可查（不含内容） |

## 7. 验收标准

- [ ] AC-01：VNC 默认仅监听 `127.0.0.1`，宿主机不对外开放端口
- [ ] AC-02：控制台可在浏览器中正常操作（键盘、鼠标、画面）
- [ ] AC-03：**控制面不直连宿主机端口**——断开 agent 通道后控制台不可用（证明必经通道）
- [ ] AC-04：`tenant` 访问他人 VM 的控制台返回 **404**
- [ ] AC-05：对外暴露需通过二次验证；未通过时配置不变更
- [ ] AC-06：VNC 密码接口**不回传**明文；数据库中为密文
- [ ] AC-07：粘贴凭据后，日志与审计中**不出现**凭据明文
- [ ] AC-08：显示设备为 `none` 的 VM 隐藏控制台入口，接口给出明确原因
- [ ] AC-09：断线后自动重连并显示重试次数；重连不产生重复会话
- [ ] AC-10：控制台会话关闭后，agent 侧与代理侧资源均被释放（无长连接泄漏）
- [ ] AC-11：截帧预览每 20s 更新；截帧失败时显示占位而非上一帧
- [ ] AC-12：多个页面同时打开时，截帧请求被服务端缓存合并
- [ ] AC-13：打开超过会话上限时明确拒绝并给出当前占用数
- [ ] AC-14：noVNC 相关资源**不在首屏包**中（可通过构建产物验证）
- [ ] AC-15：控制台流量不写日志、不落盘

## 9. 关键决策记录

> 阶段性方案，演进约定见 [`README.md`](README.md) §5.1。

| 编号 | 决策 | 理由 | 备选与否决原因 |
|---|---|---|---|
| Q-001 | VNC 流量**经 agent 反向通道承载**，控制面不直连宿主机 | 宿主机常在内网/NAT 之后，控制面无合法路径直连；且「不直连宿主机」是 ADR-0005 的红线。这条路径是既有架构下**唯一可行**的方案 | 控制面直连宿主 VNC 端口：既违背架构约束，在 NAT 环境下也不可行；在宿主机开放 VNC 端口：等于把控制台暴露到网络 |
| Q-002 | VNC 默认**仅监听 `127.0.0.1`** | 控制台是高权限入口（等同物理接触）；默认不暴露是安全基线，需要暴露时由用户显式选择并承担风险 | 默认监听 `0.0.0.0`：一旦宿主机网络可达即等于开放远程控制 |
| Q-003 | 对外暴露走**高风险二次验证** | 该操作把宿主端口暴露到网络，风险不可逆地扩大；与格式化磁盘同级 | 仅提示不验证：用户容易在未理解后果时开启 |
| Q-004 | VNC 密码**只写不读**，加密存储 | 密码可读意味着泄露即可获得控制台；「只写」让泄露面收敛到数据库密文 | 支持查看密码：便利但把高权限凭据变成可读数据 |
| Q-005 | 截帧采用**服务端短时缓存** | 详情页每 20s 一帧，若多标签/多用户同时打开会向 agent 重复请求，浪费通道带宽 | 不缓存：请求放大；前端缓存：多客户端之间无法合并 |
| Q-006 | 截帧失败时**不显示上一帧**，改显示占位与原因 | 显示过期画面会让人误以为 VM 当前状态如此——在排障场景下这种误导比空白更危险 | 保留上一帧：掩盖真实状态 |
| Q-007 | 控制台**失焦不断开**（与详情页 SSE 的失焦断开策略相反） | 控制台的典型用法是「挂着观察」（如等待安装完成），失焦断开会让它无法使用 | 沿用途详情页的失焦策略：与控制台的实际使用方式冲突 |
| Q-008 | 重连**先释放旧会话**再建新会话 | 网络抖动会产生半开连接，若不释放会累积占用配额，最终把自己挡在门外 | 直接重连：会话泄漏并耗尽上限 |
| Q-009 | 同时刻同一 VM 的控制台会话**设上限**（默认较小，如 2） | 控制台转发是长连接 + 高频数据，无上限会被单机拖垮；但需允许「同一用户多窗口」这一常见用法 | 不限制：单个 VM 可被无限会话拖垮通道；限制为 1：用户开两个窗口就会互相踢掉 |
| Q-010 | 转发数据**不落盘、不进日志** | 控制台包含屏幕内容（可能含密码、密钥、业务数据），落盘即造成旁路泄漏 | 记录流量用于排障：泄漏风险远大于排障收益 |
