## 1. 背景与目标

### 1.1 背景

[`ADR-0004`](../06-decisions/0004-adopt-openvswitch-as-network-backend.md) 定稿：采用 **Open vSwitch 作为增强模式**，同时保留 **Linux 网桥 / NAT 作为基础模式**，网络后端需**可插拔**、支持**能力探测与降级**。

这带来一个硬约束：**不具备 OVS 的节点也必须能跑起来**（降级可用），但**不能在能力缺失时静默失败**，必须明确提示并说明影响了哪些功能。

本能力是 [`CAPABILITY_MAP.md`](../01-product/CAPABILITY_MAP.md) §3 依赖链中 VM 创建的四个前置之一（节点、存储池、网络后端、任务队列）。

### 1.2 目标

- 定义**网络后端抽象**，使基础模式与增强模式对上层呈现一致的领域操作；
- agent 在纳管时**自探测网络能力并上报**，控制面据此决定启用或降级；
- 节点上存在**可用的默认网络**，M2 的虚拟机可以直接接入；
- 网络配置失败**不阻断主流程**，但必须**可见、可诊断**；
- 涉及宿主机网络连通性的操作（物理口入桥）**必须可回滚且有显式确认**。

### 1.3 不做什么（范围外）

| 不做 | 归属 |
|---|---|
| VPC 逻辑交换机、安全组、ACL | F-4-02 ~ F-4-04（P1/P2，M3） |
| 端口转发、公网 IP、静态 IP 与租约管理 | F-4-05 ~ F-4-07（M3） |
| 端口安全、端口镜像、带宽与流量配额 | F-4-08 ~ F-4-10（P2，M4） |
| 防火墙（双层策略与连接管理） | F-4-11（P1，M3） |
| 抓包与网络诊断 | F-4-12（P2，M4） |
| 网络状态展示与「修复」入口（含租约查看） | F-4-13（P1，M3）——本规格只提供**能力与降级状态**的数据源 |
| 网口与网卡管理（每口绑定交换机/安全组） | F-4-14（P1，M3） |

> 本规格在 M2 交付的是**底座**：抽象层 + 探测 + 降级 + 默认网络可用。上层网络治理能力在 M3 依此扩展。

## 2. 用户与场景

```text
作为 管理员，
我希望 节点接入后自动具备可用的网络，不必手工配置网桥和 NAT，
以便 马上就能创建虚拟机。

作为 管理员，
我希望 在该节点缺少增强网络能力时明确知道「哪些功能不可用、为什么」，
以便 决定是否去安装 OVS，而不是遇到莫名其妙的失败。
```

## 3. 功能描述

### 3.1 双模式与能力探测

```text
agent 纳管时（及后续按需重探）：
  探测宿主网络能力 → 上报能力清单（点分命名空间，见 f-6-01 R-014）
    → 控制面缓存 → 据此启用「增强模式」或降级为「基础模式」
    → 建立/校验默认网络（基础模式：网桥 + dnsmasq NAT）
    → 界面展示后端模式、能力明细与降级说明
```

### 3.2 能力项与降级映射

| 能力名（示例） | 宿主依赖 | 缺失时的降级 |
|---|---|---|
| `net.ovs` | Open vSwitch 已安装且服务可用 | 降级为**基础模式**（Linux 网桥 + NAT）；VPC 隔离 / 端口安全 / 端口镜像 / 带宽治理**不可用**并明确标注 |
| `net.ovs.openflow13` | OVS 支持 OpenFlow13 | 流表类能力（端口安全、镜像）不可用 |
| `net.ovs.meter` | OVS meter（`pktps` / `burst`） | 包速率限制不可用 |
| `net.bridge` | Linux 网桥工具链 | **整功能不可用**——无网络后端，虚拟机无法接入网络 |
| `net.dhcp` | dnsmasq | 内置 DHCP/NAT 模式不可用；静态 IP 与端口转发受影响 |
| `net.nat` | iptables / nftables | NAT 出网不可用 |

> 能力名遵循 [`f-6-01-node-onboarding.md`](f-6-01-node-onboarding.md) R-014（点分命名空间、控制面忽略未识别项）。

### 3.3 交互细节

| 步骤 | 管理员操作 | 系统响应 |
|---|---|---|
| 1 | 节点纳管完成 | 自动完成网络能力探测；节点详情展示「网络：基础模式 / 增强模式（OVS）」 |
| 2 | 查看降级说明 | 列出不可用能力及其影响的功能（如「未检测到 Open vSwitch：VPC 隔离、端口安全、端口镜像不可用」） |
| 3 | 安装 OVS 后重探 | 能力刷新，模式升级为增强模式 |
| 4 | 创建虚拟机 | 网络下拉列出**可用网络**；M2 仅系统基础网络 |

### 3.4 业务规则

| 编号 | 规则 |
|---|---|
| R-001 | 网络后端**必须可插拔**：上层只调用抽象后的领域操作，不感知底层是 Linux 网桥还是 OVS |
| R-002 | 所有宿主侧网络动作**由 agent 执行**（[ADR-0005](../06-decisions/0005-control-plane-node-agent-architecture.md)），控制面只下发领域操作 |
| R-003 | 能力探测结果由 agent **自报**；控制面**不得**假设某能力存在，必须依据上报值决定启用或降级 |
| R-004 | **缺 OVS 不阻断服务**：降级为基础模式，相关功能标注「不可用」并给出可执行的修复提示（安装命令），而非笼统报错 |
| R-005 | **网络配置失败不阻断主流程**（[`ADR-0004`](../06-decisions/0004-adopt-openvswitch-as-network-backend.md) 第 3 条）：面板启动、其他功能不受影响，仅该网络能力标记异常 |
| R-006 | 每个节点必须有且仅有一个**系统基础网络**（`vpc_switch.is_system = true`，[`DATA_MODEL.md`](../02-architecture/DATA_MODEL.md) §4.5），**不可删除**，作为未指定网络时的默认落点 |
| R-007 | **物理网卡接入网桥**（会迁移宿主默认路由，配置失误可致宿主机断网）必须：① 显式确认；② 支持回滚；③ **禁止**在无人值守流程中执行 |
| R-008 | 网络默认网络的建立**幂等**：重复执行不得产生重复网桥或冲突规则 |
| R-009 | 控制面**不得**在请求路径上直连宿主机执行网络命令；网络状态来自 agent 上报 |
| R-010 | 管理**单一 DHCP/DNS 服务实例**：同一网段上不得出现两个 DHCP 服务（见 §9 Q-005） |
| R-011 | 能力与降级状态**必须可查**，且说明「缺什么 → 影响什么功能 → 怎么修」（[`CAPABILITY_MAP.md`](../01-product/CAPABILITY_MAP.md) §5 的运行态前提口径） |

## 4. 边界与异常

| 场景 | 触发条件 | 期望行为 |
|---|---|---|
| 无 OVS | 节点未安装 Open vSwitch | 降级基础模式；VPC/端口安全/镜像/带宽标注不可用；给出安装命令 |
| 无网桥工具链 | 基础模式依赖缺失 | 该节点**网络能力整体不可用**；创建虚拟机时**前置拦截**并提示修复（不落入期望态） |
| 无 dnsmasq | 缺失 DHCP 服务 | 内置 DHCP/NAT 模式不可用；不静默失败 |
| 探测超时 | agent 探测失败 | 能力标记为**未知**（区别于「缺失」），界面如实展示；不假定可用也不假定不可用 |
| 默认网络创建失败 | 网桥/规则冲突 | 节点纳管**仍成功**（R-005）；网络标记异常并给出诊断入口 |
| 网桥被外部删除 | 有人手工 `ip link del` | 下次对账转 `error` 并提示修复；不静默重建（避免与人工操作打架） |
| 重启后运行态丢失 | 宿主机重启 | 由 agent 的启动对账恢复（见 §9 Q-006）；恢复失败则标记异常 |
| DHCP 服务冲突 | 同网段已有 DHCP（如 libvirt 默认网络） | **同一时间只允许一个**服务实例；由 agent 先行检测并跳过自身启动，同时告警（见 §9 Q-005） |
| 物理口入桥 | 管理员发起 | 走危险操作流程（确认 + 回滚）；失败**必须**恢复原网络配置，避免宿主机失联 |
| 物理口入桥回滚失败 | 回滚过程中出错 | 立即停止后续步骤并输出人工恢复指引；**不得**继续执行 |
| 多网口顺序变化 | 宿主重启后网口名变化 | 以稳定的网卡标识（如 MAC / by-id）为准，不以 `eth0` 这类内核命名顺序为准（同 [`f-5-01`](f-5-01-storage-pool.md) Q-009 的原则） |
| 节点离线 | agent 不可达 | 网络状态标记陈旧；不发新指令 |

## 5. 数据与接口

### 5.1 数据变更

| 实体 | 变更 | 说明 |
|---|---|---|
| `vpc_switch` | **复用现有字段** | `mode`（`empty` / `physical` / `nat`）、`bridge_name`、`vlan_id`、`cidr`、`gateway_ip`、`dhcp_start/end`、`uplink_if`、`is_system`、`status` 均已就绪（[`DATA_MODEL.md`](../02-architecture/DATA_MODEL.md) §4.5） |
| `node` | **复用** | 网络能力项进入节点能力清单（`capabilities`，见 `f-6-01`） |
| `audit_log` | 复用 | 网络变更、危险操作与回滚均记录 |

> **无需新增迁移**。M2 只使用 `is_system = true` 的系统基础网络记录，VPC 交换机相关字段由 M3（F-4-02）启用。

### 5.2 接口

登记至 [`API.md`](../03-api/API.md)：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/nodes/:nodeId/network` | 网络后端模式、能力清单、降级说明与默认网络状态 |
| GET | `/api/v1/nodes/:nodeId/networks` | 该节点可用网络列表（M2 仅系统基础网络；M3 起含 VPC 交换机） |

**响应要点**：必须区分三种状态——**可用** / **不可用（附原因与修复提示）** / **未知（探测失败）**，不得用布尔值掩盖「未知」。

## 6. 非功能要求

| 类别 | 要求 |
|---|---|
| 可用性 | 缺 OVS 时服务仍可用；网络配置失败不阻断面板主流程 |
| 安全 | 物理口入桥必须可回滚且需确认；禁止无人值守执行 |
| 幂等 | 默认网络与网桥创建可重复执行 |
| 可诊断 | 能力缺失、配置失败均给出「缺什么 / 影响什么 / 怎么修」 |
| 稳定性 | 以稳定标识识别网卡；重启后由对账恢复运行态 |

## 7. 验收标准

- [ ] AC-01：节点纳管后自动完成网络能力探测，界面可见后端模式（基础 / 增强）
- [ ] AC-02：**无 OVS** 的节点纳管成功，功能降级为基础模式，且**不报错阻断**
- [ ] AC-03：降级说明明确列出「不可用能力 → 影响的功能 → 安装命令」
- [ ] AC-04：安装 OVS 并重探后，模式升级为增强模式，能力项更新
- [ ] AC-05：基础模式缺失（无网桥工具链）时，创建虚拟机被**前置拦截**并提示修复，不落入期望态
- [ ] AC-06：探测失败时能力标记为**未知**，与「不可用」在界面与接口上可区分
- [ ] AC-07：每个节点存在且仅有一个系统基础网络，**无法删除**
- [ ] AC-08：默认网络创建重复执行**不产生**重复网桥或冲突规则
- [ ] AC-09：手工删除网桥后，对账将其标记为异常并提示修复，**不静默重建**
- [ ] AC-10：宿主机重启后，网络运行态由 agent 对账恢复
- [ ] AC-11：同一网段不会同时运行两个 DHCP 服务实例
- [ ] AC-12：物理口入桥走确认流程，失败时**恢复原配置**；回滚失败时停止并输出人工恢复指引
- [ ] AC-13：网络配置失败时，面板其他功能（登录、VM 列表等）**不受影响**
- [ ] AC-14：所有网络动作均由 agent 执行，控制面侧**不存在**直连宿主机的网络命令

## 9. 关键决策记录

> 阶段性方案，演进约定见 [`README.md`](README.md) §5.1。

| 编号 | 决策 | 理由 | 备选与否决原因 |
|---|---|---|---|
| Q-001 | 抽象层按**领域操作**定义（建网桥、挂接口、设 DHCP 范围、绑上行…），而非按底层命令封装 | 上层不应感知底层是 Linux 网桥还是 OVS；按命令封装会让抽象泄漏，切换后端时上游全要改 | 按命令封装：抽象形同虚设；不做抽象：ADR-0004 要求的「可插拔」无法实现 |
| Q-002 | M2 的默认网络采用**基础模式（Linux 网桥 + dnsmasq + NAT）** | M2 只需「VM 能联网」；基础模式零额外依赖，可在任何 Linux 宿主机上工作，符合「缺 OVS 也能跑」的底线要求 | M2 直接上 OVS：把 OVS 变成硬依赖，与 ADR-0004 的可插拔原则冲突 |
| Q-003 | 能力探测结果区分**「不可用」与「未知」**两种状态 | 探测失败与确认缺失是不同的：前者可能只是临时故障，若混为一谈会导致误判降级或误判可用 | 统一为布尔：无法表达「探测失败」，且会诱导系统在未知时假定某一侧 |
| Q-004 | 物理口入桥 = 危险操作：**显式确认 + 可回滚 + 禁止无人值守** | 该操作会迁移宿主默认路由，失误直接导致宿主机断网、失去远程管理能力——这是本项目可造成的最严重后果之一 | 自动执行：一次网络抖动即可能让整台宿主机失联，恢复需要物理接触 |
| Q-005 | 同网段**只允许一个 DHCP 服务实例**；agent 启动前先检测占用，冲突时跳过启动并告警 | 两个 DHCP 会给同一网段下发冲突租约，导致虚拟机网络随机失效，且极难排查。参考项目正是在此处踩坑：其「就绪检查」会 `kill` 占用 53 端口的进程，而那个进程恰是它自己的 dnsmasq，反复「杀掉→拉起」触发 systemd `start-limit-hit`（见 [`08-reference/qvmconsole/README.md`](../08-reference/qvmconsole/README.md) §4.4） | 直接抢占端口：会引发上述自噬循环；共存：租约冲突不可控 |
| Q-006 | 网络运行态由 agent 在**启动时对账恢复**，恢复失败仅标记异常不阻断 | OVS / 网桥 / 规则的运行态在重启后不自动恢复（ADR-0004 已识别），必须显式对账；但恢复失败不应让面板不可用 | 假定自动恢复：重启后虚拟机可能失去网络而无人知晓 |
| Q-007 | 系统基础网络**不可删除**，作为未指定网络时的默认落点 | 保证「任何节点上总有可用的网络」，避免用户误删后无法创建 VM；M3 的 VPC 交换机是可删的，系统网络不是 | 允许删除：一旦删除且无法轻易重建，节点等同不可用 |
| Q-008 | 网卡以**稳定标识（MAC / by-id）** 识别，不用内核命名顺序 | 重启后 `eth0`/`ens33` 的顺序可能变化，按名称操作会配置到错误的网卡（与 [`f-5-01`](f-5-01-storage-pool.md) Q-009 同源原则） | 按内核命名：重启后误配网卡，可能导致宿主机断网 |
| Q-009 | 网桥被**外部删除**时只标记异常、**不静默重建** | 静默重建会与人工维护产生「打架」（例如管理员正在手工调整网络，系统又把它改回去） | 自动重建：与人工操作冲突，且可能掩盖真实配置错误 |
