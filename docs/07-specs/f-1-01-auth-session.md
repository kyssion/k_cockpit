## 1. 背景与目标

### 1.1 背景

[`API.md`](../03-api/API.md) §4 规定「所有接口默认需要认证，公开接口必须显式标记并说明理由」。本能力是 **M2 其余全部功能的前置**——没有会话，就没有可校验的「操作人」，审计、配额、资源归属均无从落地。

### 1.2 目标

- 用户可用**用户名 + 密码**登录，密码以抗 GPU 的慢哈希存储；
- 登录成功后签发**会话令牌**，后续请求凭令牌识别身份；
- 会话可**主动失效**（登出、安全信息变更、管理员封禁、密钥轮换）；
- 会话具备**防劫持**能力（指纹绑定）；
- 会话续期只认**真实用户活动**，轮询与实时推送不延长会话。

### 1.3 不做什么（范围外）

| 不做 | 归属 |
|---|---|
| 多阶段登录流程编排（强制改密 / 安全初始化 / 2FA） | F-1-03、F-1-04（P1，M3） |
| 忘记密码、邀请注册、外部身份源 | F-1-05、F-1-13（P2，M4） |
| RBAC 授权判定、资源归属校验 | F-1-06、F-1-09（另有规格 `f-1-06-rbac.md`） |
| API Key 认证（免交互式验证的取舍） | F-1-10（P2，M4） |
| 高风险操作二次验证（428 流程） | F-10-01、F-10-02（另有规格） |

> **但本规格定义令牌分级模型**（`access` / `login` / `bootstrap`），因为它是 F-1-02 的组成部分；M2 只实现 `access`，另两种类型的**权限边界在本规格中定死**，由 M3 的多阶段流程使用。

## 2. 用户与场景

```text
作为 用户，
我希望 用账号密码登录并在会话内正常操作，
以便 无需每次请求都重新认证。

作为 用户，
我希望 能查看并撤销自己的其他登录会话，
以便 在密码疑似泄漏时切断他人访问。
```

## 3. 功能描述

### 3.1 正常流程

```text
1. 前端提交用户名 + 密码
2. 服务端校验账号状态（存在、未封禁、未删除）与密码哈希
3. 通过 → 生成 session_id、写入 user_session、签发令牌 → 返回用户信息
4. 后续请求携带令牌 → 校验签名 → 按 session_id 查会话状态 → 通过则放行
5. 每次请求若判定为「真实用户活动」→ 更新 last_active_at 并按需延长 expires_at
6. 登出 / 安全信息变更 / 封禁 → 置 revoked_at（或按 security_updated_at 批量失效）→ 令牌立即失效
```

### 3.2 交互细节

| 步骤 | 用户操作 | 系统响应 |
|---|---|---|
| 1 | 打开登录页，填写用户名密码 | 提交时按钮进入加载态；失败返回**统一文案**，不区分「用户不存在」与「密码错误」 |
| 2 | 登录成功 | 跳转至回跳地址（若有）或工作台；建立实时通道与用户信息 |
| 3 | 会话过期或失效 | 任意接口返回 401 → 前端统一跳登录页**并保留回跳地址**（[`FRONTEND.md`](../02-architecture/FRONTEND.md) §6.4） |
| 4 | 进入安全中心 → 会话与登录记录 | 展示设备、IP、时间、**当前会话标记**；可撤销其他会话（敏感项走二次验证） |

### 3.3 业务规则

| 编号 | 规则 |
|---|---|
| R-001 | 密码以 **Argon2id** 存储；存储格式自描述（含算法与参数），便于未来调整参数而不失效旧密码 |
| R-002 | 登录失败返回**统一错误文案与统一状态码**，不区分用户不存在 / 密码错误 / 账号封禁，避免用户名枚举 |
| R-003 | 登录失败**按来源 IP 与按账号双维度限流**（阈值见 §9 Q-005）；触发后返回 429 并给出可重试时间 |
| R-004 | 令牌为 **JWT（HS256）**，载荷只含 `session_id`、`user_id`、`token_type`、`exp`——**不含角色与权限**（授权每次查库，见 `f-1-06-rbac.md`） |
| R-005 | 令牌**必须同时通过签名校验与会话状态校验**（查 `user_session`）：签名有效但会话已撤销 → 拒绝 |
| R-006 | 令牌分级与权限边界：`access` 可访问全部业务接口；`login` **仅**可访问登录后续阶段接口；`bootstrap` **仅**可访问安全初始化接口。越权使用一律 403 |
| R-007 | 会话**指纹**由 `client_ip` 与 `user_agent` 摘要构成（`fingerprint` 字段）；指纹不匹配 → 拒绝该请求并要求重新登录 |
| R-008 | 会话续期只认**真实用户活动**：页面导航、显式交互、写操作会更新 `last_active_at`；**轮询与实时通道（SSE）心跳不更新**（[`FRONTEND.md`](../02-architecture/FRONTEND.md) §6.1） |
| R-009 | 会话存在**空闲超时**（`last_active_at` 起算）与**绝对上限**（`issued_at` 起算）双约束；公网会话空闲阈值更短（§9 Q-003） |
| R-010 | `user.security_updated_at` 更新（改密 / 改用户名 / 2FA 变更 / 恢复码重置）→ 该用户**全部既有会话立即失效** |
| R-011 | 用户被**封禁**（`status = banned`）→ 其全部会话立即失效，且不允许重新登录 |
| R-012 | 签名密钥支持**轮换**：轮换即更换密钥，**旧令牌全部失效**（[`PRD.md`](../01-product/PRD.md) F-1-02） |
| R-013 | 登出只撤销**当前会话**；撤销其他会话需在安全中心显式操作 |
| R-014 | 令牌与 `session_id` **不得出现在 URL、日志与审计正文**中；日志只记录 `session_id` 的前缀（便于关联排查，不足以重放） |
| R-015 | 密码与令牌**永不出现在任何接口响应中**；错误响应不得泄漏哈希、密钥或内部堆栈 |

## 4. 边界与异常

| 场景 | 触发条件 | 期望行为 |
|---|---|---|
| 用户不存在 / 密码错误 | 登录提交 | 统一 401 + 统一文案；计入限流计数 |
| 账号未激活（`pending`） | 状态为待激活 | 拒绝登录并提示「账号未激活，请联系管理员」 |
| 账号被封禁（`banned`） | 状态为封禁 | 拒绝登录；**不**提示封禁原因细节（由管理员线下告知） |
| 账号已软删除 | `deleted_at` 非空 | 按「用户不存在」统一处理 |
| 限流触发 | 超过阈值 | 429 + `Retry-After`；限流期间内正确密码**也不放行** |
| 令牌过期 | `exp` 已过 | 401，前端跳登录并保留回跳地址 |
| 令牌签名无效 | 密钥轮换后旧令牌 / 伪造 | 401；**不**区分「过期」与「签名无效」的对外文案 |
| 会话已撤销 | `revoked_at` 非空 | 401 |
| 指纹不匹配 | IP 或 UA 变化 | 拒绝并要求重新登录（§9 Q-004） |
| 会话超时（空闲 / 绝对上限） | 超阈值 | 401；前端跳登录 |
| 并发登录 | 同一账号多设备 | **允许**；各自独立会话，互不影响 |
| 数据库不可用 | 会话校验查库失败 | 允许降级为「仅签名校验」**或**直接 503 —— 见 §9 Q-007（安全优先，取 503） |
| 时钟偏移 | 服务端时间漂移 | `exp` 校验允许小幅偏移；签发与校验使用同一时钟源 |

## 5. 数据与接口

### 5.1 数据变更

| 实体 | 变更 | 说明 |
|---|---|---|
| `user` | **复用现有字段** | `password_hash`、`status`、`role`、`security_updated_at`、`force_password_change`、配额列等已就绪（[`DATA_MODEL.md`](../02-architecture/DATA_MODEL.md) §4.1） |
| `user_session` | **复用现有字段** | `session_id`、`token_type`、`fingerprint`、`client_ip`、`user_agent`、`issued_at`、`expires_at`、`last_active_at`、`revoked_at` 均已就绪（§4.2） |
| `audit_log` | 复用 | 登录成功 / 失败、登出、会话撤销、密钥轮换需记录（F-1-12） |

> **无需新增迁移**。如实现中发现缺字段，须先改 [`DATA_MODEL.md`](../02-architecture/DATA_MODEL.md)，再写迁移。

### 5.2 接口

对外契约，登记至 [`API.md`](../03-api/API.md)：

| 方法 | 路径 | 说明 | 认证 |
|---|---|---|---|
| POST | `/api/v1/auth/login` | 用户名密码登录，成功返回令牌与用户信息 | 否（公开接口，需显式标记理由） |
| POST | `/api/v1/auth/logout` | 登出当前会话 | 是 |
| GET | `/api/v1/auth/session` | 当前会话与用户信息（前端启动时调用） | 是 |
| GET | `/api/v1/auth/sessions` | 会话与登录记录列表（含当前会话标记） | 是 |
| DELETE | `/api/v1/auth/sessions/:id` | 撤销指定会话（敏感操作，需二次验证） | 是 |

**响应约定**：

- 登录成功返回用户基本信息（`id` / `username` / `role`），**不含**配额明细与安全字段；
- 令牌通过 **HttpOnly + Secure + SameSite=Strict Cookie** 下发，前端 JS **不接触**令牌——天然防 XSS 窃取，同时满足 [`FRONTEND.md`](../02-architecture/FRONTEND.md) §6.4「不落 localStorage」的要求；
- CSRF 防护见 §9 Q-008。

## 6. 非功能要求

| 类别 | 要求 |
|---|---|
| 安全 | Argon2id；统一失败文案；双维度限流；指纹绑定；令牌分级；密钥可轮换 |
| 性能 | 单次密码哈希目标 **100–500ms**（抗爆破与登录体验的平衡，需实测校准）；会话校验为一次主键/唯一索引查询 |
| 可靠性 | 数据库不可用时**拒绝**受保护请求（503），不降级为「跳过校验」 |
| 可观测性 | 登录成功与失败、限流触发、会话撤销均需可查（审计 + 日志） |
| 兼容性 | 令牌载荷变更需保持向后兼容；密钥轮换需有明确的操作顺序（见 R-012） |

## 7. 验收标准

- [ ] AC-01：正确用户名密码可登录，返回令牌与用户信息
- [ ] AC-02：密码错误、用户不存在、账号封禁返回**完全相同**的对外表现（状态码 + 文案）
- [ ] AC-03：数据库中的 `password_hash` **不是**明文，且同一密码两次存储结果不同（加盐）
- [ ] AC-04：携带有效令牌可访问受保护接口；无令牌访问返回 401
- [ ] AC-05：签名有效但 `revoked_at` 非空的令牌被拒绝
- [ ] AC-06：密钥轮换后，轮换前签发的令牌全部被拒绝
- [ ] AC-07：修改密码（`security_updated_at` 更新）后，该用户其他会话立即失效
- [ ] AC-08：用户被封禁后，既有会话立即失效且无法重新登录
- [ ] AC-09：登录失败达到阈值后触发限流（429 + `Retry-After`），限流期内正确密码也不放行
- [ ] AC-10：`login` / `bootstrap` 类型令牌访问业务接口返回 403
- [ ] AC-11：指纹不匹配的请求被拒绝
- [ ] AC-12：**轮询与 SSE 心跳不延长会话**；模拟空闲超过阈值后会话失效
- [ ] AC-13：登出后原令牌立即失效；其他设备的会话**不受影响**
- [ ] AC-14：日志与审计中**不出现**完整令牌与密码明文
- [ ] AC-15：数据库不可用时，受保护请求返回 503 而非放行

## 8. 测试要点

| 类型 | 用例 |
|---|---|
| 正常路径 | 登录 → 访问受保护接口 → 登出 → 令牌失效 |
| 边界值 | 超长用户名 / 超长密码；极小与极大阈值下的限流窗口边界 |
| 异常路径 | 用户不存在 / 密码错 / 封禁 / 软删除；过期令牌；伪造签名；会话已撤销 |
| 安全 | 用户名枚举（响应一致性）；时序攻击（密码比对耗时应与用户是否存在无关）；令牌不出现在日志 |
| 会话语义 | 续期只认真实活动；空闲超时；绝对上限；并发多设备登录 |
| 失效传播 | 改密 / 封禁 / 密钥轮换 → 全部会话失效 |
| 降级 | 数据库不可用 → 503，不跳过校验 |

## 9. 关键决策记录

| 编号 | 决策 | 理由 | 备选与否决原因 |
|---|---|---|---|
| Q-001 | 密码哈希用 **Argon2id**，存储格式自描述（含参数） | 抗 GPU / ASIC 优于 bcrypt；无 bcrypt 的 72 字节密码截断问题；参数可随硬件演进上调而无需强制全员改密 | bcrypt：成熟但有 72 字节限制且抗 GPU 较弱；scrypt：内存-时间权衡不如 Argon2 直观 |
| Q-002 | 令牌为 **JWT（HS256）**，载荷只放 `session_id` / `user_id` / `token_type` / `exp`，**必须查库校验会话状态** | 兼具「签名校验快」与「可主动失效」；角色权限不入令牌，避免授权变更后令牌仍持有旧权限 | 纯无状态 JWT：无法登出与主动失效，与 F-1-02 冲突；纯 opaque token：每次请求多一次查库且无法离线校验签名 |
| Q-003 | 会话双约束：**空闲超时 + 绝对上限**；公网空闲阈值更短 | 空闲超时贴合真实使用习惯，绝对上限限制令牌被长期窃用的窗口；公网暴露面大故收紧 | 仅绝对上限：用户长时间操作中会被强制登出；仅空闲超时：令牌可被无限续命 |
| Q-004 | 指纹 = `client_ip` + `user_agent` 摘要，**不匹配即拒绝并要求重新登录** | 「会话令牌被盗用」是高危场景，宁可让 IP 变化的用户重新登录 | 仅记录不拦截：失去防劫持意义；比对 IP 段（/24）容错：实现复杂且对移动网络仍不完善，暂不采用 |
| Q-005 | 双维度限流：**按 IP** 与**按账号**分别计数；触发后返回 429 + `Retry-After` | 按 IP 防单点爆破，按账号防分布式撞库；单一维度都可被绕过 | 仅按 IP：换 IP 即可继续撞库；仅按账号：可被用来恶意锁定他人账号（故账号维度采用**递增延迟**而非硬锁） |
| Q-006 | 令牌分级权限边界在**本规格定死**（`access` / `login` / `bootstrap`），M2 只实现 `access` | 数据模型的 `token_type` 已存在；提前定边界可避免 M3 实现多阶段登录时出现权限扩张 | 只定义 `access`：M3 需回头改协议与校验逻辑，且易出现"临时令牌能访问业务接口"的漏洞 |
| Q-007 | 会话校验依赖查库；**数据库不可用时返回 503，不降级放行** | 认证是安全边界，宁可不可用也不能出现「校验失败即放行」；与 `AGENTS.md` 第 5 节「单步失败降级」不冲突——降级适用于业务能力，不适用于安全校验 | 降级为仅签名校验：数据库故障期间被撤销的令牌会重新可用 |
| Q-008 | 令牌经 **HttpOnly + Secure + SameSite=Strict Cookie** 下发，前端 JS 不接触；CSRF 由 `SameSite=Strict` 为主、自定义请求头为纵深防御 | XSS 窃取令牌是最主要的令牌泄漏途径，`HttpOnly` 从浏览器层面根除该路径；本项目为**同源部署**（控制面同时托管前端静态资源），`SameSite` 限制不产生额外跨域成本 | 内存 + `localStorage`：XSS 可直接窃取（且 Web 存储持久化，风险窗口更长）；纯内存 + 刷新令牌：需额外实现刷新与并发重放，复杂度高且仍暴露于 XSS |
