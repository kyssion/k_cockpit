## 1. 背景与目标

### 1.1 背景

[ADR-0005](../06-decisions/0005-control-plane-node-agent-architecture.md) 定稿：控制面**不直连 libvirt、不在宿主机执行命令、不持有宿主登录凭据**；每台宿主机部署轻量 agent，作为控制面与宿主机之间的**唯一通道**。

在 [`CAPABILITY_MAP.md`](../01-product/CAPABILITY_MAP.md) §3 的依赖链中，本能力是**所有宿主侧操作的前置**：虚拟机创建、存储池、网络后端均依赖「节点在线且 agent 可用」。

### 1.2 目标

- 管理员可生成**一次性注册令牌**，并在宿主机上通过安装命令完成纳管；
- agent 注册后建立**反向长连接**，具备断线重连与重连对账能力；
- 控制面可展示节点**在线状态与能力清单**，并据此启用或降级依赖它的能力（[`CAPABILITY_MAP.md`](../01-product/CAPABILITY_MAP.md) §5）；
- 节点离线时，控制面可感知、可对账，且**不影响其他节点与已运行虚拟机**。

### 1.3 不做什么（范围外）

- 节点上虚拟机的具体操作（创建 / 电源 / 快照等）→ F-2-*；
- 节点资源清单的深度诊断与硬件直通（→ F-6-03、F-6-07）；
- 跨节点迁移与目标接管（→ F-2-15、F-6-04）；
- agent 的自动升级（[`ARCHITECTURE.md`](../02-architecture/ARCHITECTURE.md) §8 列为已知限制，本阶段不做）；
- **控制面远程卸载 agent**（见 R-013，违反架构约束）；
- 控制面主动连入 agent（直连模式为可选优化，**不作为本规格的验收范围**）。

## 2. 用户与场景

- **目标用户**：平台管理员（运维角色）。
- **使用场景**：

```text
作为 平台管理员，
我希望 用一条命令把一台宿主机接入平台，
以便 后续在此节点上创建和管理虚拟机。
```

## 3. 功能描述

### 3.1 正常流程

与 [`ARCHITECTURE.md`](../02-architecture/ARCHITECTURE.md) §4.1 一致：

```text
1. 控制面生成一次性注册令牌（可设有效期）
2. 运维在宿主机执行安装命令（内嵌控制面地址与令牌）
3. agent 用令牌注册 → 换取客户端证书（mTLS）
4. agent 自探测能力并上报 → 建立长连接
5. 控制面标记节点在线、缓存能力 → 界面可见
```

### 3.2 交互细节

| 步骤 | 管理员操作 | 系统响应 |
|---|---|---|
| 1 | 进入「节点管理」→ 生成注册令牌 | 返回令牌与可直接复制的安装命令；展示有效期（默认 24 小时，可调整）与「仅可使用一次」 |
| 2 | 在宿主机执行安装命令 | 界面节点列表出现该节点，状态先为「注册中」 |
| 3 | — | agent 完成注册与能力上报后，状态转为「在线」，能力清单可见 |
| 4 | 查看节点详情 | 展示：主机名 / IP / 架构 / OS / agent 版本 / 能力清单（可用与不可用项）/ 最后心跳时间 |
| 5 | 移除节点 | 二次验证后移除；**界面明确提示**：已运行虚拟机不受影响，且 agent 不会被远程卸载（同时给出宿主机侧卸载命令） |

### 3.3 业务规则

| 编号 | 规则 |
|---|---|
| R-001 | 注册令牌为**一次性**：成功注册后立即失效；过期或已用的令牌再次使用必须被拒绝 |
| R-002 | 令牌**默认有效期 24 小时**，生成时可由管理员调整（允许范围 5 分钟 ~ 7 天） |
| R-003 | agent 注册成功后换取客户端证书，后续连接走 **mTLS**；证书校验失败则拒绝连接并记录审计 |
| R-004 | 控制面**不持有**宿主机登录凭据（root 密码 / SSH 私钥），任何形式的持有均为越界 |
| R-005 | agent 主动连回控制面建立**反向长连接**；控制面不主动连入 agent，宿主机无需开放入站端口 |
| R-006 | agent 上报的能力清单是**能力启用 / 降级的唯一依据**（[`CAPABILITY_MAP.md`](../01-product/CAPABILITY_MAP.md) §5）；缺失能力时由控制面拦截，而非下发后期望失败 |
| R-007 | 心跳周期 **10 秒**；超过 **40 秒**（4 个周期）未收到心跳 → 节点标记**离线**，其数据保留并打「陈旧时间戳」标记 |
| R-008 | 离线节点**拒绝接收新任务**；进行中任务标记为「状态未知」 |
| R-009 | agent 重连后上报能力与运行态快照 → 控制面据此修正投影、收敛「状态未知」任务并给出结论 |
| R-010 | 节点离线**不影响**该节点上已运行的虚拟机，也**不影响**其他节点（`AGENTS.md` 第 5 节：单步失败只降级告警） |
| R-011 | **节点身份以 agent 自持的实例标识 `agent_id` 为准**（首次启动生成并落盘），不以主机名或 IP 为准——两者都可能变化 |
| R-012 | 注册时 `agent_id` 已存在 → 视为**同一节点重新注册**：更新连接信息与能力清单，保留节点 ID 与历史数据，记审计；`agent_id` 未见过但主机名与既有节点冲突 → **拒绝**并提示先移除旧节点 |
| R-013 | **移除节点只删控制面记录并吊销证书**，不远程卸载 agent：控制面既不持有宿主凭据也不在宿主机执行命令（R-004、[ADR-0005](../06-decisions/0005-control-plane-node-agent-architecture.md)）；界面提供可在宿主机手动执行的卸载命令 |
| R-014 | 能力清单为**声明式键值列表**（`name` / `available` / `detail`，能力名采用点分命名空间如 `virt.libvirt`、`net.ovs.openflow13`）；控制面**忽略未识别的能力名**，仅按已知能力参与降级判定 |
| R-015 | 协议版本兼容 **N-1**：新 agent 连旧控制面时，未知能力与未知消息字段被忽略而非报错；旧 agent 连新控制面时，新增能力一律按「不可用」降级（[ADR-0005](../06-decisions/0005-control-plane-node-agent-architecture.md)） |

## 4. 边界与异常

| 场景 | 触发条件 | 期望行为 |
|---|---|---|
| 令牌过期或已使用 | agent 携无效令牌注册 | 拒绝注册；agent 退出并提示「令牌无效或已过期，请重新生成」 |
| 证书校验失败 | 证书与注册记录不匹配 | 拒绝连接，记录审计日志，**不泄漏**校验细节给对端 |
| 心跳超时 | 40 秒未收到心跳 | 标记离线 + 数据打陈旧标记；新任务拒绝下发；进行中任务转「状态未知」 |
| agent 断线重连 | 网络恢复或 agent 重启 | 按指数退避重连（初始 1s、倍数 1.6、上限 60s、±20% 抖动）；重连后上报快照，控制面收敛「状态未知」任务 |
| 控制面不可达 | 控制面重启或网络中断 | agent 持续退避重试；**已运行虚拟机不受影响** |
| 同机重复注册 | 同一 `agent_id` 再次注册 | 按 R-012 更新连接信息，保留节点 ID 与历史 |
| 主机名冲突 | 不同 `agent_id` 但主机名与既有节点相同 | 拒绝注册并提示先移除旧节点 |
| 重装系统（`agent_id` 变化） | 新 uuid + 主机名可能相同 | 按主机名冲突处理：需管理员先移除旧节点，或生成新令牌并改主机名 |
| 并发生成令牌 | 多个管理员同时生成 | 令牌相互独立，互不影响 |
| 移除节点时仍有运行中 VM | 管理员执行移除并二次验证 | 允许移除；**不停止**其上的虚拟机，界面明确提示该后果与手动清理命令 |
| agent 版本过旧（超出 N-1） | 超出兼容窗口 | 标记节点为「需升级」，能力按最保守降级，不阻断其余功能 |

### 5.2 接口

**控制面 REST 接口**（对外契约，已登记至 [`API.md`](../03-api/API.md)）：

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/nodes/registration-tokens` | 生成一次性注册令牌与安装命令 |
| GET | `/api/v1/nodes` | 节点列表（含状态与最后心跳） |
| GET | `/api/v1/nodes/:id` | 节点详情（含能力清单） |
| DELETE | `/api/v1/nodes/:id` | 移除节点（需二次验证，返回宿主机卸载命令） |

**agent 通道协议**（内部协议，**不属** `API.md` 范围）：

| 项 | 决策 |
|---|---|
| 传输 | **gRPC over TLS（mTLS）**，双向流承载长连接 |
| IDL | **Protocol Buffers v3**（`.proto` 为唯一契约来源，生成两侧代码） |
| 服务划分 | `Bootstrap`（一元 RPC：令牌换证书、注册）与 `Channel`（双向流：心跳、能力、运行态、指令、进度） |
| 兼容策略 | 字段号**只增不复用**；新增字段必须可选；未知字段与未知能力忽略而非报错；兼容窗口 **N-1** |

> **禁止**在协议中转发 libvirt 原始 RPC；控制面与 agent 之间只传**领域操作 + 任务指令 + 进度/事件上行**（[ADR-0005](../06-decisions/0005-control-plane-node-agent-architecture.md) 第 3 条）。

## 6. 非功能要求

| 类别 | 要求 |
|---|---|
| 安全 | 令牌一次性；mTLS；控制面不持有宿主凭据；注册与校验失败记审计、不泄漏细节 |
| 可靠性 | 控制面故障不影响已运行虚拟机；节点故障不影响其他节点 |
| 性能 | 心跳周期 10s / 离线阈值 40s；设计目标：**单控制面 500 个节点**（100 节点为舒适区，500 需压测验证） |
| 可观测性 | 节点状态变化、重连、对账结论需可查（日志 + 审计） |
| 兼容性 | 协议兼容 N-1（R-015） |

## 7. 验收标准

> 每条须可验证，尽量可转为自动化测试。

- [ ] AC-01：生成令牌后，使用该令牌可成功完成一次 agent 注册
- [ ] AC-02：同一令牌**第二次**注册被拒绝，且返回可读原因
- [ ] AC-03：过期令牌注册被拒绝
- [ ] AC-04：注册成功后节点出现在列表中，状态为「在线」，能力清单非空
- [ ] AC-05：停止 agent 后，节点在 **40 秒**内转为「离线」，且数据带陈旧标记
- [ ] AC-06：节点离线期间发起的新任务被拒绝并给出原因
- [ ] AC-07：agent 重启重连后，节点恢复在线，先前的「状态未知」任务被收敛并给出结论
- [ ] AC-08：节点离线**不导致**该节点上已运行虚拟机被停止
- [ ] AC-09：生成令牌、注册失败、证书校验失败、移除节点均产生审计记录
- [ ] AC-10：控制面侧任何位置**均不存储**宿主登录凭据（可通过代码与数据检查验证）
- [ ] AC-11：同一 `agent_id` 二次注册后，节点 ID 与历史数据保持不变（R-012）
- [ ] AC-12：不同 `agent_id` 但同名注册被拒绝，且提示如何移除旧节点
- [ ] AC-13：移除节点后，该 agent 重连被拒绝（证书已吊销），且控制面**未**对宿主机执行任何远程命令
- [ ] AC-14：agent 上报含未知能力名时，控制面正常处理其余能力、不报错、不误判降级（R-014）

## 8. 测试要点

| 类型 | 用例 |
|---|---|
| 正常路径 | 完整纳管链路（生成令牌 → 安装 → 注册 → 在线 → 能力可见） |
| 边界值 | 令牌在有效期末尾使用；节点名为极长字符串；并发生成多个令牌 |
| 异常路径 | 令牌过期 / 已用 / 伪造；证书不匹配；注册过程中断网 |
| 断连对账 | 心跳超时（40s）→ 离线；重连 → 快照上报与任务收敛；退避重连时序 |
| 身份语义 | 同 uuid 重注册（保留历史）；同名异 uuid（拒绝）；重装系统场景 |
| 协议兼容 | 未知能力名、未知消息字段被忽略；N-1 版本互通 |
| 隔离性 | 单节点离线时，其他节点与已运行虚拟机不受影响 |
| 安全 | 凭据不可见于配置文件、数据库、日志；错误响应不含内部细节；移除节点不触发远程执行 |

## 9. 关键决策记录

> 本节记录 7 项关键决策及其理由（原为待决问题，2026-09-15 按业内成熟实践定稿）。**决策变更需新建 ADR 或更新本节并说明原因**。

| 编号 | 决策 | 理由 | 备选与否决原因 |
|---|---|---|---|
| Q-001 | agent 通道采用 **gRPC + Protobuf 双向流**，服务分 `Bootstrap`（一元）与 `Channel`（双向流） | 长连接、双向流、mTLS 原生支持、代码生成成熟；Protobuf 字段号机制天然支持 N-1 兼容 | 自研 HTTP/2 或 WebSocket：需自行实现协议框架、序列化与兼容策略，重复造轮子 |
| Q-002 | 心跳 **10s**、离线阈值 **40s**（4 个周期）；重连采用**指数退避 + 抖动**（1s 起、倍数 1.6、上限 60s、±20%） | 4 倍周期窗口可容忍 3 次连续丢包，与业界主流节点存活判定实践一致；抖动避免控制面重启后的重连风暴 | 固定间隔重连：控制面批量重启时会形成同步冲击；心跳过密：无谓放大控制面写入压力 |
| Q-003 | 令牌默认有效期 **24 小时**，可调范围 5 分钟 ~ 7 天 | 与主流集群引导令牌的默认 TTL 一致；既能覆盖「准备安装环境」的现实耗时，又限制泄漏窗口 | 永久有效：泄漏后风险不可控；过短（如 10 分钟）：运维准备环境时间不够 |
| Q-004 | 节点身份以 agent 持久化的 **`agent_id`** 为准；同 uuid 重注册视为同一节点（保留 ID 与历史），异 uuid 同名则拒绝 | 主机名与 IP 都可能变化，唯有 agent 自持的 uuid 稳定；「保留历史」避免节点重建导致监控与审计断链 | 以主机名为准：换主机名即变成新节点；以 IP 为准：DHCP 环境下不可用；一律新建：历史数据与配额归属断裂 |
| Q-005 | 设计目标 **单控制面 500 节点**（100 为舒适区），需压测验证 | 控制面只做编排与聚合、不搬运数据；每节点一条长连接的开销可控；该量级覆盖中小规模私有云 | 标称无上限：无法给出容量规划与告警阈值 |
| Q-006 | 能力清单为**声明式键值列表**（`name` / `available` / `detail`，点分命名空间），控制面忽略未识别项 | 新增能力**无需改协议**，天然向前兼容；控制面按已知能力判定降级，未知项忽略而非报错 | 强类型结构体：每次新增能力都要改协议与两侧代码，旧版本互通困难 |
| Q-007 | 移除节点**仅在控制面删除记录并吊销证书**，不远程卸载 agent；界面提供宿主机侧卸载命令 | 控制面不持有宿主凭据、不在宿主机执行命令是 [ADR-0005](../06-decisions/0005-control-plane-node-agent-architecture.md) 的红线；若为「便利」开远程卸载的口子，等于重新引入被否决的 SSH 通道 | 远程卸载：需要宿主凭据或反向指令通道，与架构红线冲突；纯删除不提供卸载命令：运维体验差 |
