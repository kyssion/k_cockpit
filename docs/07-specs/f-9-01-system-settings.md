## 1. 背景与目标

### 1.1 背景

系统设置是**唯一一处**同时涉及三个配置来源的界面：环境变量（部署时确定）、面板设置（运行时可改）、默认值。三者优先级含糊，会导致「我明明在界面上改了，为什么不生效」这类最难排查的问题。

[`PRD.md`](../01-product/PRD.md) F-9-01 因此明确要求：**每项标注对应环境变量名**，且**环境变量优先**。

### 1.2 目标

- 提供分标签的设置界面，覆盖基础 / 存储与网络 / 宿主机 / 调度与高级 / 安全与维护 / 日志 / 诊断；
- **每个配置项标注对应的环境变量名**，让「界面改不动」的原因一目了然；
- 明确**配置优先级**：环境变量 > 面板设置 > 默认值；
- 即时生效项**失败可回滚**，不把服务留在改坏的状态；
- 设置项与元数据**由后端下发**，前端不硬编码第二份。

### 1.3 范围与分期

F-9-01 的完整标签集是 7 个，但 M2 只交付**基础知识**（[`FRONTEND.md`](../02-architecture/FRONTEND.md) §6.8）。本规格定义**通用机制**与**基础标签**，其余标签随对应能力落地：

| 标签 | 交付批次 | 依赖 |
|---|---|---|
| **基础** | **M2** | — |
| **安全与维护** | **M2**（与 F-1-11 / F-1-12 一并） | `f-1-01` |
| 存储与网络 | M3 | 存储池（F-5-01）、网络后端（F-4-01）的完整能力 |
| 宿主机 | M3 | 宿主侧兼容性开关（域 6） |
| 调度与高级 | M3 | 调度与配额能力 |
| 日志 / 诊断 | M3 / M4 | F-9-02、F-9-03 |

> **通用机制（元数据下发、优先级判定、回滚、审计）在 M2 一次做对**，后续标签只是**增加设置项**，不再改机制。这是本规格的主要交付物。

### 1.4 不做什么（范围外）

| 不做 | 归属 |
|---|---|
| 日志查看/轮转/导出 | F-9-02（P1，M3） |

## 2. 用户与场景

```text
作为 管理员，
我希望 在界面上看到每项设置对应的环境变量名，
以便 明白为什么某一项改不动。

作为 管理员，
我希望 改坏配置时系统能自动回到改动前的状态，
以便 不会因为一次误配把面板或宿主机搞不可用。
```

## 3. 功能描述

### 3.1 配置来源与优先级

```text
最终生效值 = 环境变量  >  面板设置（持久化）  >  默认值
```

| 来源 | 说明 | 界面表现 |
|---|---|---|
| **环境变量** | 部署时确定，**不可通过界面修改** | 该输入框**只读**，标注环境变量名并说明「由环境变量设定」 |
| **面板设置** | 通过界面修改并持久化 | 可编辑；显示当前来源为「面板设置」 |
| **默认值** | 未设置时使用 | 可编辑；显示「默认值」 |

**要点**：

- 判定在**服务端**完成，界面只渲染服务端返回的「是否被环境变量锁定」；
- 被环境变量锁定的项，`PATCH` 必须**拒绝**并说明原因，不能「改了但没生效」。

### 3.2 生效方式

| 方式 | 说明 | 界面提示 |
|---|---|---|
| **即时生效** | 保存后立即应用 | 保存即生效 |
| **即时生效（可能失败）** | 应用时可能失败（如端口占用、路径不可写） | 保存后显示结果；**失败则自动回滚** |
| **重启生效** | 需重启服务 / agent 才生效 | 明确提示「重启后生效」，不制造「已生效」的错觉 |

### 3.3 交互细节

与 [`FRONTEND.md`](../02-architecture/FRONTEND.md) §5.10 一致：

| 环节 | 要求 |
|---|---|
| 分标签 | 基础 / 存储与网络 / 宿主机 / 调度与高级 / 安全与维护 / 日志 / 诊断 |
| 每项标注 | **环境变量名**（必备）、生效方式、当前来源 |
| 页面说明 | 「常规配置保存后立即生效并持久化；宿主机级选项写入系统配置文件且环境变量优先」 |
| 回滚 | 即时生效且可能失败的项提供回滚入口，并展示回滚结果 |
| 敏感项 | 走高风险二次验证（[`f-10-01`](f-10-01-high-risk-verification.md)） |
| 校验 | 保存前做类型/范围校验，错误就地提示，不提交无效值 |

### 3.4 业务规则

| 编号 | 规则 |
|---|---|
| R-001 | 配置优先级固定为 **环境变量 > 面板设置 > 默认值**，判定在服务端；界面不得自行推断 |
| R-002 | 被环境变量锁定的项**必须只读**；提交修改时服务端**拒绝**并说明原因（不允许「接受但不生效」） |
| R-003 | 每个设置项**必须声明**：键、分组、类型、默认值、**对应环境变量名**、生效方式、是否敏感、是否可回滚 |
| R-004 | 设置项元数据**由后端下发**，前端只渲染，**不允许硬编码第二份**（[`FRONTEND.md`](../02-architecture/FRONTEND.md) §6.5） |
| R-005 | 仅 **M2 已交付标签**的设置项可编辑；未交付标签的设置项**不出现在界面**（而非显示为不可用），避免半成品误导 |
| R-006 | 更新为**部分成功**语义：逐项返回结果（成功 / 失败原因），**不得**因一项失败而静默丢弃其余项的结果 |
| R-007 | 即时生效项应用失败时**必须自动回滚**到变更前的值，并在响应中标注「已回滚」及原因 |
| R-008 | 回滚**只保留最近一次变更**的前值；更早的历史由审计记录承担，不为回滚引入无限历史存储 |
| R-009 | 敏感设置项（凭据、密钥、对外暴露类）走**高风险二次验证**；敏感值**不回传明文**（只回传「已设置」与掩码） |
| R-010 | 所有设置变更**必须审计**：变更人、时间、键、旧值摘要、新值摘要、结果（成功 / 失败 / 已回滚） |
| R-011 | 审计中**不得记录敏感值**（凭据、密钥、令牌）；非敏感值可按需记录 |
| R-012 | **宿主机级**设置项经 **agent 通道**写入宿主机配置文件，控制面**不直连宿主机**（[`ADR-0005`](../06-decisions/0005-control-plane-node-agent-architecture.md)）；宿主侧执行失败同样触发回滚 |
| R-013 | 多节点场景下，宿主机级设置需明确**作用范围**（全部节点 / 指定节点），避免「改了但只改了一台」的误解 |
| R-014 | 设置变更**不得**成为绕过权限的通道：仅管理员可读写；普通用户（`tenant`）无任何可见性 |
| R-015 | 设置项的**默认值变更**（版本升级导致）不得覆盖用户显式设置过的值 |

## 4. 边界与异常

| 场景 | 触发条件 | 期望行为 |
|---|---|---|
| 环境变量已锁定 | 该项由环境变量提供 | 界面只读 + 说明；提交时服务端拒绝并指出环境变量名 |
| 应用失败 | 如端口被占用 | 自动回滚到旧值；响应标注已回滚与失败原因 |
| 回滚也失败 | 极端情况（旧值同样不可用） | 明确报告「回滚失败」并给出当前实际状态与人工处理建议，**不谎报成功** |
| 部分项失败 | 批量保存中一项失败 | 其余项正常生效；失败项单独报告（不整体回滚，除非项之间有依赖） |
| 无 `previous_value` | 首次设置该键 | 回滚操作返回明确说明（无前值可回滚） |
| 敏感值查看 | 用户请求读取凭据类设置 | 只回传掩码或「已设置」；不回传明文 |
| 并发修改 | 两个管理员同时保存 | 后提交者覆盖前者；审计记录双方变更（不做乐观锁，避免过度设计） |
| 节点离线 | 宿主机级设置需写入但节点不可达 | 明确报告「节点离线，未应用」；不标记为成功 |
| 宿主机级部分成功 | 多节点中部分节点失败 | 逐节点返回结果；不整体回滚（避免已成功的节点被无谓撤销） |
| 未交付标签 | 前端请求了 M2 未交付的设置项 | 服务端不返回该项（而非返回错误） |
| 非法值 | 类型/范围不符 | 保存前就地校验；服务端同样校验（前端校验不构成安全边界） |
| 普通用户访问 | `tenant` 打开 `/settings` | 路由不可见 + 接口 403 |

## 5. 数据与接口

### 5.1 数据变更

| 实体 | 变更 | 说明 |
|---|---|---|
| `system_setting` | **复用（已定义）** | 键值持久化设置，存储被用户改过的值。回滚所需的 `previous_value` 字段已登记于 [`DATA_MODEL.md`](../02-architecture/DATA_MODEL.md) §2.1 |
| `audit_log` | 复用 | 记录每次设置变更（含结果） |

**设计取舍**：设置项**不逐项建列**，而是 `key-value` 结构——设置项会随能力交付持续增加，逐项建列意味着每次加设置都要迁移。元数据（分组、类型、默认值、环境变量名、生效方式）在**代码中声明**（是开发者契约），数据库只存**被用户改过的值**。

> 未在数据库中的键 = 使用默认值，无需预填充。

### 5.2 接口

登记至 [`API.md`](../03-api/API.md)：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/settings` | 设置项清单（按分组，含元数据、当前生效值、来源、是否被环境变量锁定） |
| PATCH | `/api/v1/settings` | 批量更新；逐项返回结果，失败项自动回滚 |
| POST | `/api/v1/settings/rollback` | 将指定键回滚到最近一次变更前的值 |

**要点**：

- 清单接口返回的是**已交付标签**的设置项，未交付的不出现（R-005）；
- 敏感项的 `value` 字段只返回掩码或 `null` + `is_set: true`；
- 更新接口的响应需能表达「成功 / 失败 / 已回滚」三态及各自原因。

## 6. 非功能要求

| 类别 | 要求 |
|---|---|
| 安全 | 仅管理员可读写；敏感项二次验证；敏感值不回传、不入审计；不得成为权限绕过通道 |
| 一致性 | 优先级判定在服务端；界面与实际生效值不得出现分歧 |
| 可用性 | 应用失败必须回滚，不把服务留在改坏的状态；回滚失败时如实报告 |
| 可观测性 | 变更全量审计（含结果）；失败与回滚需可查 |
| 扩展性 | 新增设置项只需**声明元数据**，不改接口、不改表结构、不改前端 |

## 7. 验收标准

- [ ] AC-01：每个设置项在界面上**显示对应环境变量名**
- [ ] AC-02：由环境变量设定的项在界面**只读**，提交修改被服务端拒绝并说明原因
- [ ] AC-03：面板设置的值在服务端**优先于默认值**、**低于环境变量**
- [ ] AC-04：即时生效项应用失败时**自动回滚**，响应标注「已回滚」与原因
- [ ] AC-05：回滚失败时**如实报告**，不谎报成功
- [ ] AC-06：回滚接口可把指定键恢复到最近一次变更前的值
- [ ] AC-07：敏感项的接口响应**不含明文**，仅掩码或「已设置」
- [ ] AC-08：审计记录包含变更人、时间、键、结果，且**不含敏感值**
- [ ] AC-09：设置项元数据由后端下发——改后端（如新增一项）后**前端无需改动**即可正确渲染
- [ ] AC-10：M2 未交付标签的设置项**不出现在**界面与接口响应中
- [ ] AC-11：`tenant` 访问设置页面与接口均被拒绝（403）
- [ ] AC-12：宿主机级设置经 agent 写入；节点离线时明确报告「未应用」而非成功
- [ ] AC-13：批量更新中单项失败，其余项正常生效且逐项报告结果
- [ ] AC-14：非法值被服务端拒绝（绕过前端校验直接请求时同样拒绝）
- [ ] AC-15：版本升级引入的默认值**不覆盖**用户显式设置过的值

## 9. 关键决策记录

> 阶段性方案，演进约定见 [`README.md`](README.md) §5.1。

| 编号 | 决策 | 理由 | 备选与否决原因 |
|---|---|---|---|
| Q-001 | 优先级固定为**环境变量 > 面板设置 > 默认值** | 环境变量代表部署者的意图（如容器编排下发的配置），界面修改不应悄悄覆盖它——这正是 PRD 要求「环境变量优先」的原因 | 面板设置优先：容器重启后配置被界面值覆盖，部署意图丢失，且难以排查 |
| Q-002 | 被环境变量锁定的项在界面**只读**，提交时**服务端拒绝** | 「能改但改完不生效」是最难排查的体验；拒绝并说明原因，把问题消灭在当下 | 允许修改但静默不生效：制造「界面与现实不一致」的经典陷阱 |
| Q-003 | 设置项存 **`key-value` 结构**，不逐项建列 | 设置项会随能力交付持续增加（本规格已分 7 个标签分期），逐项建列意味着每次加设置都要迁移 | 逐项建列：迁移频繁，且新增设置要动表结构 |
| Q-004 | 元数据在**代码中声明**，数据库只存**被改过的值** | 元数据是开发者契约（默认值、类型、环境变量名），随代码版本走；数据库只承担用户覆盖值 | 元数据入库：代码与数据双份来源，易漂移；且未改过的项也需预填充 |
| Q-005 | 更新采用**部分成功**语义，逐项报告 | 一次保存多个设置是常态；整体成败语义会让用户无法判断哪些生效了 | 原子语义：一项失败全部撤销，用户需反复试错 |
| Q-006 | 即时生效项失败**自动回滚** | 支持「即时生效」的项（端口、路径、日志级别）一旦改错会直接影响可用性，自动回滚是保命线 | 仅报告失败不回滚：用户可能已失去访问面板的路径（如改了监听端口） |
| Q-007 | 回滚**只保留最近一次**，不建历史表 | 设置变更频率低，「最近一次」已覆盖绝大多数误配场景；更早历史由审计承担 | 保留 N 次历史：为低频场景引入历史表与清理任务，属过度设计 |
| Q-008 | 未交付标签的设置项**不出现在界面** | 显示为不可用会让用户以为「功能坏了」，也会引发「为什么不让我改」的疑问 | 显示但禁用：半成品误导 |
| Q-009 | 敏感值**不回传**、**不入审计** | 与 VNC 密码、凭据管理同一原则：只写不读，泄漏面收敛到存储密文 | 请求时回传明文：把高权限凭据变成可读数据 |
| Q-010 | 宿主机级设置**经 agent 写入**，并按节点逐一报告结果 | 控制面不直连宿主机（[`ADR-0005`](../06-decisions/0005-control-plane-node-agent-architecture.md)）；多节点场景下「整体成功/失败」会掩盖部分节点的真实状态 | 整体成败语义：用户无法知道哪台没改成功 |
