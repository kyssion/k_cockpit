## 1. 背景与目标

### 1.1 背景

[`DATA_MODEL.md`](../02-architecture/DATA_MODEL.md) §4.6 明确：`vm` 表中的 `status` / `vcpu` / `memory_mb` / `disk_gb` / `ip_summary` 是**投影字段**——「以虚拟化层为准，缓存只做投影，不参与业务判定」。

同时 [`CAPABILITY_MAP.md`](../01-product/CAPABILITY_MAP.md) §3 要求「工作台与监控的展示层只读缓存，**不在请求路径直连虚拟化层**」。这两条约束决定了本能力的核心设计：**数据从缓存读，状态由 agent 上报驱动更新**。

### 1.2 目标

- 列表与详情**秒开**（读缓存，不等宿主机）；
- 状态与资源占用经**实时通道**推送，无需手动刷新；
- 电源操作**状态机正确**（按当前状态动态可用），且与任务队列的资源锁一致；
- 数据**陈旧时如实告知**，不把过期数据当实时数据展示；
- 删除时的**磁盘处理语义明确**（连盘删除 or 保留磁盘）。

### 1.3 不做什么（范围外）

| 不做 | 归属 |
|---|---|
| 编辑虚拟机配置 | F-2-05（P1，M3） |
| 磁盘与设备管理、快照、重装、迁移 | F-2-06 / F-2-07 / F-2-11 / F-2-15（P1，M3） |
| VNC / SPICE 控制台 | F-2-08（P0，另有规格） / F-2-09（P2，M4） |
| 来宾自动化（改密、扩容） | F-2-10（P1，M3） |
| 标签、备注、分组**的元数据写入虚拟化层** | F-2-16（P1，M3）——M2 支持备注与分组的**本地编辑** |
| 定时任务 | F-7-05（P2，M4） |

## 2. 用户与场景

```text
作为 用户，
我希望 打开列表就能看到所有虚拟机的当前状态与资源占用，
以便 一眼判断哪些需要处理。

作为 用户，
我希望 电源按钮只在我能操作时可用，
以便 不会点了之后才发现当前状态不允许。

作为 用户，
我希望 删除虚拟机时能明确选择是否保留磁盘，
以便 不会误删需要保留的数据。
```

## 3. 功能描述

### 3.1 数据来源与新鲜度

```text
agent 周期上报运行态（含 VM 状态、资源占用）
  → 控制面更新投影缓存（vm 表 + 内存投影）
  → 经 SSE 通道推送前端（列表 2s 增量 / 详情 3s 全量）
  → 前端渲染；数据陈旧时标注
```

**关键区分**：

| 数据 | 来源 | 新鲜度表达 |
|---|---|---|
| 状态、资源占用、IP | agent 上报（投影） | 正常实时更新；节点离线 → 标记**陈旧** |
| 名称、备注、分组 | 控制面（元数据） | 即时（用户操作的直接结果） |
| 配置详情（机型、引导等） | 虚拟化层经 agent 上报 | 带「最近同步时间」 |

### 3.2 交互细节

与 [`FRONTEND.md`](../02-architecture/FRONTEND.md) §5.3.1 / §5.3.3 一致，要点：

| 环节 | 要求 |
|---|---|
| 列表视图 | 表格 / 卡片双视图；列配置见前端文档 |
| 分组与搜索 | 分组（全部/状态/模板/自定义）；搜索在**已加载数据**上客户端过滤 |
| 实时 | 进入即建 SSE；断线 5s 重连；从其他页返回**先渲染缓存再静默更新** |
| 电源按钮 | 按当前状态**动态可用**；loading 语义见前端文档（依赖状态变化解除） |
| 批量操作 | 底部浮出操作条；提示「N 台已选 · M 台运行中」；含被锁定项时提前提示 |
| 详情标签页 | **惰性挂载**（仅当前可见标签拉数据） |
| 详情实时 | 3s 全量；**失焦 10s 断开**，聚焦立即重连并重置速率增量基准 |
| 空态 | 插图 + 两个创建入口 |
| 维护模式 | 页面虚化 + 顶部提示；**禁用新建与电源操作** |

### 3.3 业务规则

| 编号 | 规则 |
|---|---|
| R-001 | **展示层只读缓存**，不在请求路径直连虚拟化层（[`CAPABILITY_MAP.md`](../01-product/CAPABILITY_MAP.md) §3） |
| R-002 | **投影不得参与业务判定**：`vm.status` 等投影字段仅用于展示；任何业务决策（能否开机、能否删除）都必须基于**实时探测或任务队列的资源锁**，不得凭投影下结论 |
| R-003 | 节点离线时，其虚拟机的数据**保留并标记陈旧**，**不显示为「已停止」或任何确定状态**——离线 ≠ 关机 |
| R-004 | 电源操作**按状态机动态可用**；不可用的操作在前端禁用并说明原因，后端同样校验（前端禁用不构成安全边界） |
| R-005 | 电源操作一律**入任务队列**（[`f-7-01`](f-7-01-task-queue.md)），同一 VM 互斥；接口立即返回任务标识 |
| R-006 | **关机为优雅关机**（需来宾配合，可能超时）；超时后可执行**强制断电**；两者在界面上是不同操作，不自动降级（避免静默强杀） |
| R-007 | **重置（reset）仅对暂停态可用**（[`PRD.md`](../01-product/PRD.md) F-2-04） |
| R-008 | 区分**内部错误暂停**与**普通暂停**，界面文案与可用操作不同 |
| R-009 | 删除必须显式选择**磁盘处理方式**：`disk_action = delete`（连磁盘删除）或 `keep`（保留磁盘）；**默认不选中**，需用户主动选择（避免默认删盘造成数据丢失） |
| R-010 | 删除**被锁定**的虚拟机需先解锁；批量删除中若含锁定项，**整体提示并列出**，不静默跳过 |
| R-011 | **归属过滤**沿用 [`f-1-06`](f-1-06-authorization.md)：`tenant` 只见自己的 VM；访问他人 VM 返回 **404** |
| R-012 | 详情页编辑期间，后台推送**不得覆盖未提交的输入**；用「配置签名」区分「统计心跳」与「配置真变化」，仅后者重建表单（[`FRONTEND.md`](../02-architecture/FRONTEND.md) §5.3.3） |
| R-013 | 列表的**资源计量条**数据同样来自推送；无数据时显示占位而非 0（避免误读为「占用为零」） |
| R-014 | 维护模式（`node.maintenance_mode`）下，**禁止**该节点虚拟机的创建与电源操作；已运行虚拟机不受影响 |
| R-015 | 一次性拉取的数据量有上限（默认分页 50，最大 200）；超出时由服务端筛选，不整表拉取 |

## 4. 边界与异常

| 场景 | 触发条件 | 期望行为 |
|---|---|---|
| 节点离线 | agent 不可达 | 该节点 VM 数据标记**陈旧**；电源操作**拒绝**并提示「节点离线」；状态不显示为已停止 |
| 状态陈旧后恢复 | agent 重连对账 | 投影更新为真实值，陈旧标记消失 |
| 投影与真实状态不一致 | 手工在宿主机操作了 VM | 下次对账收敛；**差异暴露给用户**而非静默修正（[`ARCHITECTURE.md`](../02-architecture/ARCHITECTURE.md) §5） |
| 电源操作进行中重复点击 | 用户连点 | 按 [`f-7-01`](f-7-01-task-queue.md) 资源锁串行；前端 loading 依赖状态变化解除 |
| 关机超时 | 来宾未响应 | 任务保持运行（不谎报完成）；界面提示可执行强制断电 |
| 批量操作部分失败 | 其中若干台状态不允许或无权限 | 逐台独立任务；界面区分成功与失败，失败项给原因 |
| 批量操作含锁定 VM | 选中项中有锁定项 | 提前提示并列出，由用户决定是否继续 |
| 删除时任务进行中 | 该 VM 有正在运行的任务 | 拒绝删除并提示先完成任务或取消 |
| 删除后实时通道仍推该 VM | 通道数据滞后 | 前端按 ID 去重并移除；不出现「幽灵行」 |
| 列表数据超过分页上限 | 数据量大 | 服务端筛选 + 分页；提示用户使用筛选而非全量浏览 |
| 资源占用数据缺失 | 采集未覆盖或上报延迟 | 显示占位符，不显示 0 |
| 详情页编辑中收到配置变更推送 | 后台同步 | **不覆盖**未提交输入；按配置签名判断是否需重建表单 |

## 5. 数据与接口

### 5.1 数据变更

| 实体 | 变更 | 说明 |
|---|---|---|
| `vm` | **复用现有字段** | 投影字段 `status` / `vcpu` / `memory_mb` / `disk_gb` / `ip_summary` 与元数据 `remark` / `group_name`（[`DATA_MODEL.md`](../02-architecture/DATA_MODEL.md) §4.6） |
| `task` | 复用 | 电源与删除操作的任务记录（[`f-7-01`](f-7-01-task-queue.md)） |
| `audit_log` | 复用 | 电源操作、删除（含磁盘处理方式）均记录 |

> **无需新增迁移**。

### 5.2 接口

登记至 [`API.md`](../03-api/API.md)：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/vms` | 列表（筛选 / 排序 / 分页；归属过滤） |
| GET | `/api/v1/vms/:id` | 详情（含配置、投影状态与最近同步时间） |
| POST | `/api/v1/vms/:id/power-actions` | 电源操作（`start` / `shutdown` / `reboot` / `poweroff` / `reset`），返回任务标识 |
| POST | `/api/v1/vms/batch-actions` | 批量操作（`vm_ids` + 动作），逐台返回任务标识 |
| DELETE | `/api/v1/vms/:id` | 删除（`disk_action = delete` \| `keep`，**必填**） |

**要点**：

- 列表响应需带**数据新鲜度**字段（最近同步时间 / 是否陈旧），供前端标注；
- 电源操作接口在做任何事之前，必须基于**实时探测**校验状态合法性（R-004）；
- 批量操作逐台校验并逐台入队，**一次请求可部分成功**，响应中逐台给出结果。

## 6. 非功能要求

| 类别 | 要求 |
|---|---|
| 性能 | 列表与详情读缓存，响应不受宿主机延迟影响；SSE 消息处理 < 5ms（[`FRONTEND.md`](../02-architecture/FRONTEND.md) §6.7） |
| 一致性 | 投影与真实状态差异**暴露**而非静默修正 |
| 可用性 | 节点离线只影响该节点的写操作与数据新鲜度，不影响其他节点与列表整体可用 |
| 安全 | 归属过滤；前端禁用不构成安全边界 |
| 数据安全 | 删除默认**不**选磁盘处理方式，防止误删盘 |

## 7. 验收标准

- [ ] AC-01：列表与详情**不直连宿主机**，节点离线时仍能打开（数据标记陈旧）
- [ ] AC-02：节点离线时 VM 状态**不显示为「已停止」**
- [ ] AC-03：状态与资源占用经 SSE 自动更新，无需手动刷新
- [ ] AC-04：详情页失焦 10s 后停止推送，聚焦立即恢复
- [ ] AC-05：电源按钮按状态动态可用；后端对非法状态的请求同样拒绝
- [ ] AC-06：关机是优雅关机；超时不自动降级为强制断电，由用户决定
- [ ] AC-07：`reset` 仅在暂停态可用，其他状态返回明确错误
- [ ] AC-08：同一 VM 的并发电源操作按资源锁串行，不产生状态错乱
- [ ] AC-09：删除必须显式选择磁盘处理方式，未选择时拒绝
- [ ] AC-10：批量删除含锁定项时，整体提示并列出，不静默跳过
- [ ] AC-11：`tenant` 只能看到自己的 VM；请求他人 VM 返回 **404**
- [ ] AC-12：详情页编辑中收到推送，未提交的输入**不被覆盖**
- [ ] AC-13：资源占用无数据时显示占位符，不显示 0
- [ ] AC-14：维护模式下，该节点 VM 的创建与电源操作被禁止
- [ ] AC-15：删除某 VM 后，实时通道的滞后消息不会造成列表出现「幽灵行」
- [ ] AC-16：列表超过分页上限时使用服务端筛选与分页，不整表拉取

## 9. 关键决策记录

> 阶段性方案，演进约定见 [`README.md`](README.md) §5.1。

| 编号 | 决策 | 理由 | 备选与否决原因 |
|---|---|---|---|
| Q-001 | 列表与详情**读投影缓存**，不在请求路径直连虚拟化层 | 直连宿主机取状态会让列表在节点多、VM 多时极慢，且一个慢节点会拖垮整个页面（[`CAPABILITY_MAP.md`](../01-product/CAPABILITY_MAP.md) §3 已明确此约束） | 实时查询：延迟不可控，且违背既有架构约束 |
| Q-002 | 投影**不参与业务判定**，写操作前必须实时校验 | 投影可能滞后；若凭投影判断「已停止」就允许删除，可能在 VM 实际运行时执行危险操作 | 凭投影判定：一次延迟就可能导致误操作 |
| Q-003 | 节点离线时数据**标记陈旧**，状态**不显示为已停止** | 离线 ≠ 关机。显示「已停止」会诱导用户执行开机等无意义操作，甚至误判业务已中断 | 显示为「未知」并隐藏所有信息：用户失去参考；显示为「已停止」：误导 |
| Q-004 | 关机与强制断电是**两个独立操作**，超时**不自动降级** | 静默强杀可能造成来宾文件系统损坏；何时放弃等待应由用户判断 | 自动降级：数据损坏风险不可接受 |
| Q-005 | 删除时磁盘处理方式**必填且默认不选中** | 删除 VM 是高频操作，默认值即「用户最可能接受的选项」；若默认「连盘删除」，误操作代价是数据永久丢失 | 默认连盘删除：风险过高；默认保留：会累积无主磁盘，但可事后清理——两者相较取其轻 |
| Q-006 | 搜索在**已加载数据**上客户端过滤，超量时服务端筛选 | 客户端过滤无延迟、交互流畅；但数据量增长后必须回退到服务端，故需在分页上限处切换 | 一律服务端：每次输入都发请求，体验与负载都差；一律客户端：数据量大时不可行 |
| Q-007 | 批量操作**逐台独立任务**，允许部分成功 | 与 [`f-2-02`](f-2-02-vm-create.md) Q-004 同源：逐台可追踪、可取消、失败不污染其他台 | 单一批次任务：失败语义与取消粒度都无法表达 |
| Q-008 | 详情页用**配置签名**区分统计心跳与配置真变化 | 3s 全量推送会频繁触发；若无差别重建表单，用户正在编辑的输入会被反复打断 | 每次推送都重建：编辑体验不可用；不重建：配置真变化时前端显示过期 |
| Q-009 | 维护模式下**禁止创建与电源操作**，但**不影响已运行虚拟机** | 维护模式的意义是「不再引入变更」，而非「停止业务」；后者应通过显式关机完成 | 一并停止运行中的 VM：维护模式会变成高危操作 |
