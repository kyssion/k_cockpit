## 1. 背景与目标

### 1.1 背景

创建虚拟机是 M2 完成标志（「建 VM → 开机 → 控制台 → 关机 → 删除」）的起点，也是**依赖最多的一步**——[`CAPABILITY_MAP.md`](../01-product/CAPABILITY_MAP.md) §3 列出它同时依赖节点在线、存储池、网络后端、配额与任务队列，任一缺失都应给出**可执行的修复提示**而非笼统失败。

同时它是**不可逆操作**（创建虚拟磁盘、定义虚机），失败必须能干净回滚。

### 1.2 目标

- 提供 9 步创建向导的完整工程契约；
- 关联资源（节点 / 存储池 / 网络 / ISO）**前置校验**，缺失时拦截并给出修复指引；
- 表单规则**由后端下发**，前端不硬编码第二份（[`FRONTEND.md`](../02-architecture/FRONTEND.md) §2.4）；
- 创建**幂等**——重复提交不产生两台虚拟机；
- 支持**批量创建**，每台独立可追踪、可取消；
- 失败时按声明范围**干净回滚**。

### 1.3 不做什么（范围外 / 后续迭代）

| 不做 | 归属 |
|---|---|
| **模板克隆**方式 | 依赖模板能力（F-3-01，P1，M3） |
| **导入已有磁盘**、**导入 OVF-OVA** 方式 | F-2-13（P1，M3）；M2 向导中该两张卡片置灰并说明原因 |
| **硬件直通**设备选择 | F-2-06（P1，M3）；M2 展示该步骤，节点无 IOMMU 时禁用并说明 |
| **首次启动初始化**（cloud-init / ConfigDrive / OpenWrt） | F-2-17（P1，M3）；M2 仅提供「不初始化」选项 |
| 编辑已有虚拟机配置 | F-2-05（P1，M3） |
| 创建后的电源操作 | F-2-04（另有规格 `f-2-04`） |

> M2 交付的创建方式是 **ISO 安装**（不依赖模板，是最基本的可用路径）。

## 2. 用户与场景

```text
作为 用户，
我希望 按向导一步步填完就能创建一台可开机的虚拟机，
以便 不必了解 libvirt 的 XML 细节。

作为 用户，

以便 不用等任务跑到一半才失败。
```

## 3. 功能描述

### 3.1 流程

```text
打开向导 → 拉取表单元数据（字段定义 / 联动规则 / 可选值 / 前置条件）
  → 逐步填写（步骤 2 起自动存草稿）
  → 提交前完整校验（前端汇总 + 后端权威校验）
  → 【高危确认】如涉及（见 R-006）
  → 幂等键生成 → 任务入队（1 台 1 任务）→ 立即返回任务标识
  → agent 执行：建盘 → 定义 XML → 启动 → 网络绑定
  → 按阶段上报进度 → 完成或失败（附回滚结果）
```

（执行阶段划分见 [`ARCHITECTURE.md`](../02-architecture/ARCHITECTURE.md) §4.2）

### 3.2 交互细节

与 [`FRONTEND.md`](../02-architecture/FRONTEND.md) §5.3.2 一致，要点：

| 环节 | 要求 |
|---|---|
| 步骤 1 创建方式 | 4 张卡片；M2 仅「ISO 安装」可用，其余置灰并说明何时可用 |
| 步骤 6 系统配置 | 初始化方式在 M2 仅有「不初始化」，并说明后续版本提供 |
| 步骤 8 硬件直通 | 节点无 IOMMU 能力时禁用，并给出「需要开启 IOMMU」的提示 |
| 步骤 9 确认信息 | 分组摘要 + **预估资源占用** + **配额余量校验**；有缺失项时禁用提交并给出定位链接 |
| 草稿 | 步骤 2 起自动保存，24h 有效；**敏感字段不落草稿**（见 R-008） |
| 提交后 | 跳列表并高亮新行，任务栏显示进度 |

### 3.3 业务规则

| 编号 | 规则 |
|---|---|
| R-001 | **前置校验必须前置**：节点在线且具备能力、存在可用存储池、存在可用网络、配额充足。任一不满足 → **在提交时拦截**并给出可执行修复提示，不落入期望态 |
| R-002 | **表单规则由后端下发**（字段定义、联动规则、默认值、可选值、字段可见性），前端只渲染与禁用；**禁止**前端硬编码第二份规则（[`FRONTEND.md`](../02-architecture/FRONTEND.md) §2.4、§6.5） |
| R-003 | **校验分两层**：前端校验为体验（快速反馈、分步校验）；**后端校验为权威**；后端拒绝时必须返回**可定位到具体字段**的错误信息 |
| R-004 | 创建**必须幂等**：同一幂等键重复提交返回**已有任务**，不创建第二台虚拟机 |
| R-005 | **配额双重校验**：提交时校验（给用户反馈）+ 实际下发前再校验（防止并发超卖） |
| R-006 | 创建属**高风险操作链的起点**（会占用磁盘与计算资源），按 F-10-01/02 的判定口径决定是否走二次验证（典型场景：超出常规规格、管理员为他人创建） |
| R-007 | 批量创建 = **N 个独立任务**（一台一个），共享 `batch_key` 以便分组与批量取消；单台失败**不影响**其他 |
| R-008 | **敏感字段不得落草稿**：初始密码、密钥等字段不写入 localStorage；草稿仅保存非敏感的配置项 |
| R-009 | **任务参数必须脱敏**（[`f-7-01`](f-7-01-task-queue.md) R-009）：初始凭据写入 `vm_credential`（加密存储），**不得**出现在 `task.params` |
| R-010 | 虚拟机名在**节点内唯一**（`uniq_vm_node_name`）；重名时拒绝并给出可用建议名 |
| R-011 | **失败必须回滚**：回滚范围在任务定义中声明（典型为「删除已创建的磁盘与虚机定义」）；回滚失败需显式报告，不得静默吞掉 |
| R-012 | 创建属重操作，**必须入队**（[`f-7-01`](f-7-01-task-queue.md) R-001），接口只返回任务标识 |
| R-013 | **归属自动注入**：`owner_id` 取当前用户，**忽略**请求体中的该字段（[`f-1-06`](f-1-06-authorization.md) R-007） |
| R-014 | 创建前必须确认**目标节点与存储池均可用**；不得在离线节点上入队（应拒绝并提示） |
| R-015 | 网口顺序（`vm_interface.order`）从 0 起**连续无空洞**，增删后归一化（[`DATA_MODEL.md`](../02-architecture/DATA_MODEL.md) §4.8 约束） |

## 4. 边界与异常

| 场景 | 触发条件 | 期望行为 |
|---|---|---|
| 无可用存储池 | 节点无 `ready` 状态的池 | 提交被拦截，提示「请先创建存储池」并给出跳转链接 |
| 无可用网络 | 节点网络能力不可用 | 提交被拦截，提示网络后端缺失及修复方式（见 [`f-4-01`](f-4-01-network-backend.md)） |
| 节点离线 | 目标节点不可达 | 提交被拦截（不允许在离线节点入队，避免任务悬挂） |
| 配额不足 | 超出用户配额 | 提交被拦截，明确列出超出的维度与当前余量 |
| 并发超卖 | 两请求同时通过提交校验 | 下发前二次校验拦截其中一个，任务标记失败并说明原因 |
| 重名 | 目标节点已存在同名 VM | 拒绝并提供建议名（如加后缀 `-2`） |
| 重复提交 | 用户重复点击 / 网络重试 | 幂等键命中 → 返回已有任务，不重复创建 |
| 批量部分失败 | N 台中 M 台失败 | 各任务独立终态；界面明确区分成功与失败，失败项给出原因 |
| 建盘成功但定义 XML 失败 | 阶段失败 | 按回滚范围清理已建磁盘；任务标记失败并列出**已完成的步骤** |
| 启动失败 | 磁盘已建、虚机已定义 | 保留虚机定义与磁盘（便于人工修复），任务标记失败并说明；**不**自动删盘（避免误删用户可能想保留的数据） |
| 取消 | 用户取消创建任务 | 按 [`f-7-01`](f-7-01-task-queue.md) R-007 处理；界面提示「已完成步骤可能不会回滚」 |
| ISO 不存在 | 选择的 ISO 已被删除 | 提交时校验失败，提示重新选择 |
| 资源在任务执行中被删除 | 存储池/ISO 在排队期间被删 | 执行前重新校验，失败则任务失败并说明 |
| 草稿过期 | 超过 24h | 提示「草稿已过期」，清空并从头开始 |
| 规格超限 | vCPU / 内存超过节点剩余能力 | 提交时提示并给出节点当前可用值 |

## 5. 数据与接口

### 5.1 数据变更

| 实体 | 变更 | 说明 |
|---|---|---|
| `vm` | **复用现有字段** | `node_id`、`name`、`owner_id`、`vcpu`、`memory_mb`、`disk_gb`、`remark`、`group_name` 等（[`DATA_MODEL.md`](../02-architecture/DATA_MODEL.md) §4.6）。注意 `status` / `vcpu` 等为**投影字段**，以虚拟化层为准 |
| `vm_interface` | **复用** | `order`、`is_primary`、`switch_id`、`model`、`mac`、`allowed_addresses`（§4.8） |
| `vm_credential` | **复用** | 初始凭据加密存储（§4.9）——这是 R-009 脱敏要求的落点 |
| `task` / `task_stage` | **复用** | 创建任务与阶段（[`f-7-01`](f-7-01-task-queue.md)）；`params` 中携带 `batch_key` |
| `audit_log` | 复用 | 创建请求、校验拒绝、回滚结果均记录 |

> **无需新增迁移**。

### 5.2 接口

登记至 [`API.md`](../03-api/API.md)：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/vms/create-form` | **表单元数据**：字段定义、联动规则、默认值、可选值、前置条件检查结果（按 `node_id` 上下文） |
| POST | `/api/v1/vms` | 创建虚拟机（支持 `count` 批量），返回任务标识（批量时返回任务列表） |

**创建请求要点**：

- 必须携带 **`client_token`**（幂等键，由前端生成）；
- 可选 `batch_key`（批量时由前端生成，便于分组与批量取消）；
- **不得**包含 `owner_id`（服务端注入）；
- 初始凭据字段独立于 `params` 传递，落 `vm_credential`，**不进**任务参数。

**表单元数据响应要点**：

- 每个字段包含：类型、必填、默认值、校验规则、可见性条件（联动）、禁用原因（如「该节点不支持硬件直通」）；
- 逐项给出**前置条件状态**（存储池 / 网络 / 配额 / 节点能力），便于前端在向导开头就提示。

## 6. 非功能要求

| 类别 | 要求 |
|---|---|
| 安全 | 参数脱敏；`owner_id` 服务端注入；敏感字段不落草稿；批量创建同样受配额与权限约束 |
| 一致性 | 提交校验 + 下发前校验双层；执行前重新确认前置资源仍存在 |
| 幂等 | `client_token` 保证重复提交不产生重复资源 |
| 可观测性 | 每台 VM 独立任务，阶段可查；批量失败可定位到具体台次 |
| 性能 | 表单元数据接口需缓存节点能力与可选值，避免每次打开向导都全量探测 |
| 可维护性 | 联动规则单一来源在后端；前端不硬编码 |

## 7. 验收标准

- [ ] AC-01：向导能拉取到表单元数据并正确渲染 9 步
- [ ] AC-02：M2 中「模板克隆」「导入磁盘」「导入 OVF-OVA」三张卡片置灰并说明原因
- [ ] AC-03：无可用存储池时，提交被拦截并提示「请先创建存储池」及跳转链接
- [ ] AC-04：节点离线时提交被拦截（不入队）
- [ ] AC-05：配额不足时提交被拦截，且明确列出超出的维度
- [ ] AC-06：**同一 `client_token` 重复提交只产生一个任务**、一台虚拟机
- [ ] AC-07：并发提交导致配额超卖时，下发前的二次校验拦截后一个
- [ ] AC-08：重名提交被拒绝并给出建议名
- [ ] AC-09：批量创建产生 N 个独立任务，共享 `batch_key`，单台失败不影响其他
- [ ] AC-10：初始密码**不出现在** `task.params`、日志与审计中
- [ ] AC-11：草稿在 24h 内可恢复，且**不包含**敏感字段
- [ ] AC-12：建盘成功但定义失败时，已建磁盘被按声明范围回滚清理
- [ ] AC-13：启动失败时保留磁盘与虚机定义（不自动删盘），任务失败原因明确
- [ ] AC-14：请求体中传入 `owner_id` 被忽略，落库归属为当前用户
- [ ] AC-15：网口顺序从 0 起连续无空洞
- [ ] AC-16：创建成功后，列表能通过实时通道看到新 VM 并高亮
- [ ] AC-17：后端校验失败时，错误可定位到具体字段（前端能按照错误定位到步骤与字段）

## 9. 关键决策记录

> 阶段性方案，演进约定见 [`README.md`](README.md) §5.1。

| 编号 | 决策 | 理由 | 备选与否决原因 |
|---|---|---|---|
| Q-001 | 表单规则（字段、联动、默认值、可见性）**由后端下发**，前端不硬编码 | 创建向导的规则极多且会频繁调整；两处维护必然漂移，且「后端改了前端没改」会造成用户填了非法组合才发现失败 | 前端硬编码：漂移只是时间问题；文档约定同步：靠人记，不可靠 |
| Q-002 | **提交校验 + 下发前校验**双层 | 提交时校验为用户体验（快速反馈）；但提交到执行之间资源可能变化，且并发请求可能同时通过校验造成超卖 | 仅提交时校验：会超卖；仅下发前校验：用户填完 9 步才被告知配额不足 |
| Q-003 | 幂等键由**前端生成**（`client_token`）并随请求提交 | 用户重复点击与网络重试都发生在客户端，只有前端生成的 token 才能识别「这是同一次提交」 | 后端按参数哈希去重：两次规格相同的合法创建会被误判为重复 |
| Q-004 | 批量 = **N 个独立任务** + `batch_key` 分组，而非一个任务含 N 个子项 | 独立任务可分别追踪、取消与重试；单台失败不污染其他台的结论 | 单任务多子项：失败语义复杂（整体失败？部分失败？），且取消粒度无法到单台 |
| Q-005 | 草稿存 localStorage 但**排除敏感字段** | 草稿的价值在于「填了 8 步不想重来」；而密码等泄露风险远大于便利收益（与 [`f-1-01`](f-1-01-auth-session.md) Q-008 同源原则：敏感信息不落客户端持久存储） | 全量存草稿：明文凭据留在浏览器；完全不存草稿：长表单体验差 |
| Q-006 | **启动失败不自动删盘**，保留虚机定义与磁盘 | 启动失败多为可修复问题（如引导顺序、ISO 损坏）；自动删盘会让用户在排查前就丢失已创建的磁盘 | 一律回滚：可能在用户已找到原因时把可复用的成果删掉；不回滚任何步骤：失败会留下无主的磁盘与定义垃圾 |
| Q-007 | 初始凭据走 `vm_credential`（加密），**不进** `task.params` | 任务参数会被列表、详情、导出、审计多处读取与展示，是泄漏高发面；凭据需要独立的加密与访问控制 | 放进 params：脱敏逻辑要覆盖所有读取路径，漏一处即泄漏 |
| Q-008 | **不允许在离线节点上入队**创建任务 | 任务会永久停留在无法执行的状态；且「未知」语义会让用户困惑（节点都没在线，任务怎么可能在执行） | 允许入队等待：队列中堆积无法执行的任务，且状态语义混乱 |
| Q-009 | 执行前**重新校验**前置资源仍存在（存储池、ISO、节点能力） | 排队期间资源可能被删除或能力发生变化；不复校验会在执行到中途才失败，回滚成本更高 | 不复查：失败点后移，回滚范围更大 |
