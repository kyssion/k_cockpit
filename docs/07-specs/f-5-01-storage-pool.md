## 1. 背景与目标

### 1.1 背景

[`ARCHITECTURE.md`](../02-architecture/ARCHITECTURE.md) §5 明确：**控制面只保存路径与元数据**，磁盘的格式化、挂载、空间探测等**宿主侧动作全部由 agent 执行**（[ADR-0005](../06-decisions/0005-control-plane-node-agent-architecture.md)）。控制面**不得**直连宿主机或执行底层命令。

格式化是**不可逆**操作，误操作会销毁数据——本规格的主要篇幅因此花在安全校验上。

### 1.2 目标

- 管理员能**看到节点上有哪些磁盘**，以及各自的状态（未分配 / 已挂载 / 已被系统使用）；
- 能把一块空闲磁盘**格式化为存储池并挂载**，指定为节点的默认池；
- 能**删除存储池**（并在有虚拟机占用时拒绝）；
- 能查看存储的**空间分配视图**（已用 / 可用 / 未挂载 / 未分配）；
- **任何一步都不会误伤系统盘或已有数据的盘**。

### 1.3 不做什么（范围外 / 后续迭代）

| 不做 | 归属 |
|---|---|
| **分区管理**（在磁盘上创建/删除分区） | 本能力的**后续迭代**——M2 使用整盘即可支撑 VM 创建闭环 |
| **LVM 的 PV / VG / LV 创建与删除** | 同上；数据模型已预留 `kind = lvm_vg` |
| 存储卷（多盘聚合 / 条带 / 镜像） | F-5-02（P2，M4） |
| 用户存储空间、文件上传与管理 | F-5-03 ~ F-5-05（P1，M3） |
| 目录共享到虚拟机（9p VirtFS） | F-5-06（P2，M4） |
| 容量与配额视图的**分档预警与超限转只读** | F-5-07（P1，M3）——本规格只提供池级空间数据 |
| 安装期选择用户存储镜像所在磁盘 | 属**部署脚本**（`install.sh`）职责，不是控制面功能 |

## 2. 用户与场景

```text
作为 管理员，
我希望 把宿主机上的一块空闲磁盘变成平台可用的存储池，
以便 在其上创建虚拟机。

作为 管理员，
我希望 在格式化之前明确看到这块盘上有什么、会不会影响系统，
以便 不会因为一次误操作毁掉数据。
```

## 3. 功能描述

### 3.1 正常流程

```text
1. 管理员进入「存储管理」，选择节点
2. 控制面展示该节点的磁盘清单（由 agent 上报）：设备、容量、状态、是否系统盘
3. 管理员选中一块「空闲」磁盘 → 选择文件系统（默认 ext4）→ 提交
4. 【高风险二次验证】（格式化不可逆，见 R-004）
5. 任务入队 → agent 执行：校验 → 格式化 → 挂载 → 回报
6. 控制面写入 storage_pool 记录（status = ready）→ 界面可见
7. 首次创建时可设为该节点默认池
```

### 3.2 交互细节

| 步骤 | 管理员操作 | 系统响应 |
|---|---|---|
| 1 | 打开某节点的存储管理 | 磁盘清单：设备路径、容量、状态标签（`空闲` / `已挂载` / `系统盘` / `已被存储池使用`） |
| 2 | 选中磁盘 | 展示该盘的**风险提示**：若已存在分区或文件系统，明确标注「该盘似乎包含数据」 |
| 3 | 提交创建 | 弹出二次验证；确认文案要求**输入设备名**（如 `/dev/sdb`）才能提交 |
| 4 | — | 任务中心出现任务，阶段可见（校验 → 格式化 → 挂载 → 完成） |
| 5 | 创建完成后 | 存储池列表出现该池；若为第一个池，提示「已设为该节点默认存储池」 |
| 6 | 删除存储池 | 若有虚拟机占用则**拒绝并列出占用者**；否则二次验证后卸载并删除 |

### 3.3 业务规则

| 编号 | 规则 |
|---|---|
| R-001 | **所有宿主侧动作由 agent 执行**；控制面只下发领域操作并保存元数据，不得直连宿主机或执行命令 |
| R-002 | 存储池创建 / 删除属**重操作**，一律入任务队列（[`f-7-01-task-queue.md`](f-7-01-task-queue.md) R-001），接口只返回任务标识 |
| R-003 | 存储操作与迁移**全局串行**（[`CAPABILITY_MAP.md`](../01-product/CAPABILITY_MAP.md) §4）：同一时刻只允许一个存储池变更任务运行 |
| R-004 | 格式化属**不可逆操作**，必须：① 进入高风险清单（F-10-01/02）；② 走二次验证；③ 要求用户**输入设备名**确认 |
| R-005 | **设备安全校验（双端）**：控制面与 agent 各自校验，任一不通过即拒绝。校验项见 §4 |
| R-006 | 每个节点**至多一个默认存储池**；创建第一个池时自动设为默认，之后可手动切换 |
| R-007 | 存储池状态取值与 `storage_pool.status` 一致：`ready`（可用）/ `unmounted`（已配置但未挂载）/ `unallocated`（设备存在但未分配）/ `error`（异常，附原因） |
| R-008 | **删除存储池前必须做占用检查**：若池内存在被虚拟机使用的磁盘，**拒绝删除**并列出占用者 |
| R-009 | 空间数据（`total_bytes` / `usable_bytes`）由 agent **随指标周期上报**，不按需实时探测；界面展示需标注数据新鲜度 |
| R-010 | 控制面**不得**假设设备路径稳定；以 `(node_id, device_id)` 作为存储池的唯一标识（`uniq_storage_pool_node_device`），路径仅作展示 |
| R-011 | 存储池操作仅**管理员**可用（[`f-1-06-authorization.md`](f-1-06-authorization.md) §3.1：存储池管理为 `admin` 专属） |
| R-012 | 单次操作只处理**一块设备**；批量格式化不在本规格范围（避免一次失误放大影响面） |
| R-013 | 所有存储池变更记录审计（谁、何时、对哪个设备、做了什么、结果） |

## 4. 边界与异常

### 4.1 格式化前的安全校验（核心）

**控制面侧**（数据校验，快速失败）：

| 校验项 | 拒绝条件 |
|---|---|
| 节点状态 | 节点不在线 / agent 不可用 / 能力清单中缺少所需工具 |
| 设备存在性 | 设备不在 agent 上报的最新清单中 |
| 设备已被池占用 | `(node_id, device_id)` 已存在未删除的 `storage_pool` 记录 |
| 权限 | 非 `admin` |

**agent 侧**（实机校验，防线在最后）：

| 校验项 | 拒绝条件 |
|---|---|
| **系统盘** | 设备或其分区承载 `/`、`/boot`、`/boot/efi`、swap |
| **已挂载** | 设备或任一子分区处于挂载状态（`findmnt` 命中） |
| **被 LVM / RAID / LUKS 占用** | 是 PV、RAID 成员或加密卷成员 |
| **存在分区表或文件系统** | 已有分区表或可识别的文件系统 → **默认拒绝**；若确需覆盖，须由管理员显式勾选「我确认该盘数据可被销毁」后重试（仍走二次验证） |
| 设备正被其他任务操作 | 存在进行中的任务占用该设备 |

> **校验必须双端**：控制面校验提供快速反馈，agent 校验才是最终防线（控制面的信息可能滞后）。

### 4.2 其他边界

| 场景 | 触发条件 | 期望行为 |
|---|---|---|
| 磁盘清单为空 | 节点无可用磁盘 | 明确提示「该节点没有可用磁盘」，不显示空表格 |
| agent 执行中失败 | 格式化成功但挂载失败 | 任务标记失败并给出**已完成步骤**；`storage_pool` 记录保持 `error` 或按回滚范围清理（见 R-011 回滚声明） |
| 挂载点被占用 | 目标挂载点已有内容 | agent 拒绝并报明确原因 |
| 删除时节点离线 | 节点不可达 | **拒绝**并提示「节点离线，无法确认占用情况」；不允许盲目删除 |
| 并发创建 | 两个请求同时格式化同一设备 | 按设备加锁；后者排队或直接拒绝（设备已被占用） |
| 默认池被删除 | 删除当前默认池 | 允许；随后节点处于「无默认池」状态，创建 VM 时提示需先指定 |
| 空间上报中断 | 节点离线 | 池标记数据**陈旧**（沿用 §6.1 的新鲜度语义），不显示为 0 |
| 设备热插拔 | 设备消失 | 下次探测时池转 `error` 并说明设备不存在 |

## 5. 数据与接口

### 5.1 数据变更

| 实体 | 变更 | 说明 |
|---|---|---|
| `storage_pool` | **复用现有字段** | `node_id`、`device_id`、`device_path`、`kind`、`fs_type`、`mount_path`、`total_bytes`、`usable_bytes`、`is_default`、`status` 均已就绪（[`DATA_MODEL.md`](../02-architecture/DATA_MODEL.md) §4.4） |
| `vm` | **不新增字段** | VM 与存储池的关联采用**隐式路径归属**（见 §9 Q-007），删除前由 agent 扫描池内磁盘与控制面 VM 记录比对 |
| `audit_log` | 复用 | 创建、删除、默认池切换、校验拒绝均记录 |

> **无需新增迁移**。

### 5.2 接口

登记至 [`API.md`](../03-api/API.md)：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/nodes/:nodeId/disks` | 块设备清单（设备、容量、状态标签、是否系统盘、是否含数据） |
| GET | `/api/v1/nodes/:nodeId/storage-pools` | 该节点的存储池列表（含空间与新鲜度） |
| POST | `/api/v1/storage-pools` | 创建存储池（格式化 + 挂载），返回任务标识 |
| PATCH | `/api/v1/storage-pools/:id` | 设为默认池 / 修改备注 |
| DELETE | `/api/v1/storage-pools/:id` | 删除存储池（含占用检查），返回任务标识 |

**创建请求的强制字段**：`node_id`、`device_id`、`fs_type`、可选 `is_default`、以及 `confirm_device_name`（用户输入的设备名，须与服务端认定的设备名**完全一致**）。

## 6. 非功能要求

| 类别 | 要求 |
|---|---|
| 安全 | 双端校验；系统盘与已挂载设备一律拒绝；格式化需输入设备名确认；仅管理员可用 |
| 数据保护 | **绝不**在未确认的情况下销毁数据；含数据的设备需显式二次确认 |
| 一致性 | 控制面记录与 agent 实际挂载状态由对账收敛（[`ARCHITECTURE.md`](../02-architecture/ARCHITECTURE.md) §5：最终一致，差异**暴露给用户**而非静默修正） |
| 性能 | 磁盘清单可由 agent 缓存上报，避免每次打开页面都扫描块设备 |
| 可观测性 | 创建 / 删除任务的阶段与结果可查；空间数据带时间戳 |

## 7. 验收标准

- [ ] AC-01：磁盘清单能正确区分「空闲」「已挂载」「系统盘」「已被存储池使用」
- [ ] AC-02：**系统盘**在任何情况下都无法被选为格式化目标（控制面与 agent 双重拒绝）
- [ ] AC-03：已挂载的设备被拒绝，并给出明确原因
- [ ] AC-04：含分区表或文件系统的设备**默认被拒绝**；显式确认后方可继续
- [ ] AC-05：提交创建需输入设备名，输入不匹配时无法提交
- [ ] AC-06：创建走高风险二次验证（428 流程）
- [ ] AC-07：创建全程入队执行，接口立即返回任务标识
- [ ] AC-08：同一时刻只有一个存储池变更任务在运行（与迁移串行）
- [ ] AC-09：创建成功后 `storage_pool` 记录 `status = ready`，空间数据非零
- [ ] AC-10：首个池自动成为默认池；同节点无法存在第二个默认池
- [ ] AC-11：池内有虚拟机磁盘时，删除被拒绝并列出占用者
- [ ] AC-12：节点离线时删除被拒绝（无法确认占用）
- [ ] AC-13：格式化成功但挂载失败时，任务标记失败并给出**已完成的步骤**
- [ ] AC-14：`tenant` 角色无法调用任何存储池接口（403）
- [ ] AC-15：创建 / 删除 / 校验拒绝均产生审计记录
- [ ] AC-16：所有磁盘操作均由 agent 执行，控制面侧代码**不存在**直连宿主机的路径

| 类型 | 用例 |

## 9. 关键决策记录

> 本节决策为**阶段性方案**：随项目迭代可能调整。调整方式见 [`README.md`](README.md) §3.1（重大变更走 ADR，细节调整直接更新本规格并记变更记录）。

| 编号 | 决策 | 理由 | 备选与否决原因 |
|---|---|---|---|
| Q-001 | M2 只支持**整盘格式化 + 挂载**（`kind = local`，默认 ext4）；分区管理与 LVM 作为本能力的后续迭代 | M2 的完成标志是「建 VM 闭环」，一块可用存储池即可支撑；分区与 LVM 涉及更复杂的撤销语义，先跑通主链路 | 一次做全：M2 周期拉长，且分区/LVM 的失败回滚更难验证 |
| Q-002 | 格式化前**双端校验**（控制面 + agent），且含数据的设备**默认拒绝** | 格式化不可逆。控制面信息可能滞后，最终防线必须在能直接观察设备的 agent 侧 | 仅控制面校验：信息滞后会放大误操作风险；仅 agent 校验：用户要等到任务跑起来才知道被拒，体验差 |
| Q-003 | 危险确认要求**输入设备名**，而非简单点「确认」 | 格式化销毁数据的后果不可逆，需要与「删除节点」同级的确认强度；输入设备名能强迫用户核对目标 | 仅弹窗确认：用户容易条件反射式点击 |
| Q-004 | 默认池唯一性由**应用层事务**保证，并配 `uniq_storage_pool_default` 条件唯一索引兜底 | 应用层事务提供可读的错误提示，索引防止并发下的数据错乱——两者互补而非二选一 | 仅应用层：并发下可能突破；仅索引：错误信息对用户不友好 |
| Q-005 | 空间数据随**指标采集周期**上报，不按需实时探测 | 探测块设备与文件系统开销不小；存储容量变化是分钟级而非秒级；与 F-8-01 复用同一采集链路 | 按需探测：每次打开页面都触发宿主机扫描，浪费且拖慢响应 |
| Q-006 | 删除池前由 **agent 扫描池内磁盘**并与控制面 VM 记录比对，得出占用者 | 宿主机是真相来源；由能直接读目录的 agent 扫描最可靠 | 仅靠控制面记录：宿主机上手工放置的磁盘文件会被漏掉 |
| Q-007 | VM 与存储池采用**隐式路径归属**，**不**在 `vm` 表新增 `storage_pool_id` 外键 | 避免为「删除池」这一低频操作增加表结构与迁移；路径前缀足以判定归属 | 新增外键：更健壮，但需改数据模型 + 迁移，且迁移/克隆后路径变化仍需同步维护；若后续出现路径归属不可靠的案例，再评估改为显式外键 |
| Q-008 | 存储池变更与迁移**全局串行** | 两者都涉及全局资源（存储布局 / 跨节点数据搬运），并发执行风险不可控（[`CAPABILITY_MAP.md`](../01-product/CAPABILITY_MAP.md) §4） | 仅按设备加锁：迁移会同时触及源与目标节点的多块设备，无合适锁键 |
| Q-009 | 设备标识以 `(node_id, device_id)` 为准，`device_path` 仅作展示 | 设备路径会变（重启后 `/dev/sdb` 可能变 `/dev/sdc`），uuid / by-id 才稳定 | 以路径为准：设备顺序变化会导致操作错盘——这是最危险的失误类型 |
