# 目录按层收敛：路由层 / 接口层 / 服务层 / 数据库层

## 背景与决策依据

- 现状分层已存在但**不可见**：路由层=router、接口层=handler、服务层=`{compute,network,storage,ops,node}`+platform 混着的 13 个业务包、数据库层=model+platform/database。
- 本方案与 ADR-0010「按域分组、不引入技术分层」冲突。按「ADR 只增不改」惯例，**新增 ADR-0012** 取代其组织方式：域分组保留为 service/ 内的二级结构，分层成为一级组织原则。
- 用户已确认：①数据库层要抽 repository/DAO；②platform 的 13 个业务服务包全部迁入 service/platform/。
- **范围判断**：repository 全量抽取涉及约 6 万行、上千处 GORM 调用点，不可一次安全完成。本次完成**目录结构一步到位 + node 域（最小域，6 文件）作为 repo 范式完整迁移**，其余域按同一范式**分批迁移**（写入规范与 ADR 的迁移路线，每域一 commit，测试护航）。

## 目标结构（一眼识层）

```
internal/
├── router/          # 路由层：路由注册与角色声明（本次按域拆成多文件）
├── handler/         # 接口层：HTTP 参数解析与响应（位置不动，按域分子包）
├── service/         # 服务层：业务逻辑
│   ├── compute/  network/  storage/  ops/  node/
│   └── platform/   # 身份与权限域服务（原 platform 13 个业务包迁入）
├── repository/      # 数据库访问层：SQL/GORM 查询集中于此（本次建层 + node 域范式）
│   └── node/
├── model/           # 数据库层：表模型（跨域共享，维持不拆）
├── platform/        # 基础设施（瘦身后仅剩）：api / authz / audit(写侧) / config /
│   │                # cryptoutil / database / logging / version
├── agent/           # agent 契约 + mock（未来 agent 二进制的边界，不动）
└── devdata/         # 开发期演示数据（不动）
```

命名规范（写入 CODING_STANDARDS）：顶级目录名即层名——`router`/`handler`/`service`/`repository`/`model`/`platform`(基础设施)/`agent`；层内二级目录=业务域，与 `handler/*` 同名对应。

## 实施步骤

### 第一步：机械目录迁移（纯 git mv + import 重写，一个 commit）

1. `mkdir internal/service`，`git mv internal/{compute,network,storage,ops,node} internal/service/`；
2. `git mv` platform 的 12 个业务子包（auth、settings、invite、useradmin、apikey、risk、auditlog、reqlog、passaudit、authkey、accesscontrol、mailer）到 `internal/service/platform/`；**audit 写侧留在 platform**（ADR-0010 论证过它必须比 auth 更底层，且无 HTTP 语义，属横切基础设施）；authz（Viewer 判定 + 角色中间件）同理留在 platform；
3. 全仓 sed 重写 import：`k_cockpit/internal/<域>` → `k_cockpit/internal/service/<域>`、`k_cockpit/internal/platform/<业务包>` → `k_cockpit/internal/service/platform/<业务包>`。注意 `platform/auth` 与 `platform/authz`/`platform/authkey` 前缀重叠，替换必须带包边界（如 `platform/auth"` 或按包名精确匹配），替换完用 `go build ./...` 验证无残留；
4. 影响面（已探明）：约 150~200 个 Go 文件；非 Go 侧（CI / 脚本 / web / go.mod）零影响。

### 第二步：router 按域拆分（一个 commit）

- `router.go`（1111 行）拆为：`router.go`（入口 Register + 全局中间件 + requireAuth/adminOnly 装配）+ `routes_compute.go` / `routes_network.go` / `routes_storage.go` / `routes_ops.go` / `routes_node.go` / `routes_platform.go`，路由集合与顺序逐条不变；
- `route_coverage_test.go` 适配新的包路径前缀。

### 第三步：repository 层立层 + node 域范式迁移（一个 commit）

1. 新建 `internal/repository/node/`：`Repo` 结构体持 `*gorm.DB`，把 `service/node` 中全部 GORM 查询原样下沉为方法（不改语义，只换位置）；
2. `service/node.Service` 依赖从 `*gorm.DB` 换成 `*nodeRepo.Repo`，业务判断留在 service；
3. CODING_STANDARDS 新增「分层与 repository 规范」：目标态 service 不直接 import gorm、查询全部下沉 repo、repo 不含业务判断与 HTTP 语义；存量域豁免、分批迁移中。

### 第四步：文档同步（一个 commit）

- 新增 `docs/06-decisions/0012-*.md`（分层决策 + repository 迁移路线 + 对 ADR-0010 的取代说明）+ 决策索引 README 登记；
- AGENTS.md §4 目录树与 §2 说明、ARCHITECTURE.md §3 模块划分、DATA_MODEL.md（8 处路径）、DEPLOYMENT.md（2 处）、CHANGELOG；
- `docs/06-decisions/0010` 本身不改（只增不改）。

### 验证（每步之后）

`go build ./... && go vet ./... && gofmt -l` → `go test ./...` 全绿 → 最后跑 `cd web && pnpm test:e2e` 冒烟（真实拉起服务，验证装配与路由全链路）。

## 明确不做（本次）

- 其余域（compute/network/storage/ops/platform）的 repository 迁移——按范式分批做，每域一 commit，compute 最大放最后；
- model 按域拆分（维持 ADR-0010 的跨域共享决策）；
- handler 更名（Go 惯例 handler 即接口层名）；
- 引入接口抽象/mock 替身（repo 用具体类型，测试需要替身时再抽接口，YAGNI）。
